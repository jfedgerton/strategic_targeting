# Strategic targeting, v2 pipeline (R + Stan)

Two-stage spatial choice model of MID initiation and target selection, estimated jointly in Stan. Branch `v2-rebuild`; the old code is reference only. A 24-cell real-data run of dd48506 is on the cluster; the changes of 2026-10-25 are for the next run.

## 1. Question and design

How do states choose whom to attack? Two axes of power enter together, material (CINC share) and relational (position in the IGO network), and the paper's typology reads a state's preferred target off both: a **bully** targets states below it on both axes, a **challenger** targets states above it, a **peer** targets states near it, and the off-diagonal hybrids mix the two.

Two stages, estimated jointly in one Stan program per family.

| stage | unit | outcome | regressors |
|---|---|---|---|
| 1, initiation | state-year (i, t) | y1 = 1 when i initiates at least one non-escalation event in t | W (initiator power changes, levels, controls) and the inclusive value IV of stage 2 |
| 2, target choice | event (i → j, t), choice set = every other system member at t | the chosen j | the gap x_ij = (M_i − M_j, R_i − R_j) at t − 1 through a quadratic utility around an ideal gap μ_n = μ0 + X_n β + a_i, dyadic controls Z, target intercept b_j |

Two model families and four variants each (eight model codes). Stage 1 is identical in all eight; only the stage-2 utility and hence the IV differ, so LOO compares like with like.

| code | `D_mode` | `joint` | stage-2 targeting space |
|---|---|---|---|
| M1m / M2m | 1 | – | material only (x = dM, scalar μ, scalar Σ, Ω 2×2 over (c, a)) |
| M1r / M2r | 2 | – | relational only (x = dR) |
| M1a / M2a | 3 | 0 | both axes, independent (Σ diagonal, corr(a_1, a_2) = 0; corr(c, a_d) free) |
| M1b / M2b | 3 | 1 | both axes, joint (full Σ, full Ω) |

M1 (`stan/m1_latent_additive.stan`) has state random effects (c_i, a_i) and target intercepts b_j; M2 (`stan/m2_ame.stan`) adds the AME term u_i'v_j with K latent dimensions. The main grid is 3 samples × 8 models × 4 lags = 96 cells. A ninth model code outside the grid, **M1c** (`stan/m1_context.stan`, section 11), is M1b with group-specific ideal-point shifts and tolerance scales over the stage-2 event groups bilateral / coalition leader / joiner.

## 2. Quick start

Three commands. Locally (from the repo root; needs R 4.3 / rstan 2.32, peacesciencer 1.2.0):

```
Rscript v2/R/compile_models.R && Rscript v2/R/01_build_data.R        # 1. compile the five Stan programs (about 2 min each, 3 GB) + build (about 3 min)
Rscript v2/R/02_fit_model.R --sample=fmid --lag=3 --model=M1b          # 2. one main cell (add --dry_run=TRUE to validate only)
Rscript v2/R/03_extract.R --fit=v2/output/fit_fmid_lag3_all_pr_M1b.rds # 3. post: typology; 04_compare.R needs the eight fits of a group
```

On Roar (submit from the repo root; `00_env.sh` is sourced by every job and exports `R_MAKEVARS_USER=v2/env/Makevars`; account `jfe4_cr_default`, partition `basic`, for the fits; the `open` account for the build, dry runs, tests and post-processing). **Deploy into a fresh clone (or an empty `v2/output/`)**: every post-processing tool refuses a fit whose recorded Stan source hash differs from the compiled program's (`assert_fit_stan_current()`), so fits of an earlier program left in `v2/output/` are never mixed in silently, but they are also not cleaned up; the 24-cell run of dd48506 lives in another directory on the cluster.

```
git clone <repo> strategic_targeting_v2 && cd strategic_targeting_v2 && git checkout v2-rebuild   # fresh clone: empty v2/output
sbatch v2/slurm/01_build.sbatch                                                     # 1. compile + build (open account, minutes)
sbatch --account=open --time=01:00:00 --mem=16G --cpus-per-task=2 --wrap='source v2/slurm/00_env.sh && Rscript v2/tests/run_tests.R'   #    unit tests, INSIDE a job
sbatch --account=open --export=ALL,DRY_RUN=TRUE --time=00:30:00 --mem=16G --cpus-per-task=1 v2/slurm/02_main_grid.sbatch   # Roar check: 96 cells assemble, no sampling (open)
bash v2/slurm/submit_main_grid.sh                                                   # 2. MAIN GRID (jfe4_cr_default): the 48 M1 cells, then the 48 M2 cells afterok
sbatch v2/slurm/03_post.sbatch                                                      # 3. extraction + comparison per (sample, lag), array 0-11 (fails unless all 8 fits of a group exist)
```

The tests and the pilot run inside a job (`sbatch --wrap` as above, or `srun --account=open --pty bash`, then `source v2/slurm/00_env.sh`), never bare on the login node: `00_env.sh` loads the gcc and R modules and sets the library path, and the Stan tests load the compiled programs. Without compiled models (`v2/stan/build/`) the model tests skip (15 skips) and only the data-coding tests run.

`submit_main_grid.sh` submits `02_main_grid.sbatch` twice: the M1 cells (array indices 0-11, 24-35, 48-59, 72-83) and, with `--dependency=afterok` on that array and `--kill-on-invalid-dep=yes`, the M2 cells (12-23, 36-47, 60-71, 84-95), so every M2 task finds its cell's M1 fit in `output/` and starts from it (section 7, "M2 initial values"). One dependency on the whole M1 array was chosen over per-cell dependencies as the simpler scheme; with `kill-on-invalid-dep` a failed M1 task cancels the M2 array instead of leaving it pending forever (resubmit the failed cell and the M2 array by hand). Recipes:

```
bash v2/slurm/submit_main_grid.sh                                  # the whole grid
M1_IDX=24-35 M2_IDX=36-47 bash v2/slurm/submit_main_grid.sh        # ONE LAG: lag 3 (lag 1: 0-11 / 12-23; lag 5: 48-59 / 60-71; lag 10: 72-83 / 84-95)
M2_OPTS="--time=10-00:00:00" bash v2/slurm/submit_main_grid.sh     # per-array sbatch options (M1_OPTS / M2_OPTS; the M2 cells need about twice the M1 walltime)
bash v2/slurm/submit_main_grid.sh --account=open --export=ALL,DRY_RUN=TRUE --time=00:30:00 --mem=16G --cpus-per-task=1   # extras go to both arrays
```

**AME K = 1 at lag 3** (PI request 2026-10-26; the main grid stays K = 2). The lag-3 M1 array is submitted once and TWO M2 arrays depend on it: the K = 2 array of the main grid and a K = 1 array whose tasks get `SWITCHES="--ame_K=1"` (`M2_SWITCHES`, exported to the M2 array only; `02_main_grid.sbatch` appends it to the `02_fit_model.R` call). The K = 1 cells are named `<sample>_lag3_all_pr_M2x_K1` (`cell_name()`), so they never collide with the `_K2` main-grid outputs, and both arrays start from the SAME K-free M1 fits (`m1_spec()`: the M1 lookup drops the K). `M1_JOB=<id>` reuses an M1 array submitted earlier instead of submitting a new one. Verified against a stub `sbatch` in `test_spec.R`; the three submissions are

```
M1_IDX=24-35 M2_IDX=36-47 bash v2/slurm/submit_main_grid.sh                                 # (a) + (b): M1 array <id>, then the K = 2 M2 array afterok:<id>, kill-on-invalid-dep=yes
M1_JOB=<id> M2_IDX=36-47 M2_SWITCHES="--ame_K=1" bash v2/slurm/submit_main_grid.sh          # (c): the K = 1 M2 array afterok:<id>, kill-on-invalid-dep=yes; no new M1 array
sbatch --export=ALL,SWITCHES="--ame_K=1" v2/slurm/03_post.sbatch                            # post: the 4 M1 fits + the 4 _K1 fits per group; compare_*_<sample>_lag<h>_all_pr_K1.csv
```

which issue `sbatch --parsable --array=24-35 v2/slurm/02_main_grid.sbatch`, `sbatch --parsable --array=36-47 --dependency=afterok:<id> --kill-on-invalid-dep=yes v2/slurm/02_main_grid.sbatch` (SWITCHES empty) and the same M2 command with `SWITCHES=--ame_K=1` in its environment; task 36 of the last then runs `Rscript v2/R/02_fit_model.R --sample=mid --lag=3 --model=M2m --dry_run=FALSE --threads_per_chain=8 --ame_K=1`. `M2_SWITCHES="--ame_K=2"` is refused (that is the main grid). `03_post.sbatch` names the eight fits of a group through `cell_spec()` (the M1 names never carry a K) and `04_compare.R --ame_K=1` writes the group `<sample>_lag<h>_all_pr_K1` (`compare_group_name()`; the K = 2 group keeps its documented name). The K = 1 post-processing re-extracts the four M1 fits (identical outputs, overwritten).

`--array` in the extras is refused (it would override both index lists). A plain `sbatch v2/slurm/02_main_grid.sbatch` still runs all 96 cells at once; an M2 cell whose M1 fit FILE is missing falls back to random inits (loudly, recorded in the fit), an M1 fit that exists but is unusable (pilot, stale, other data, other cell) stops the task (audit fix 2026-10-26).

Robustness: `PRESET=noww2 bash v2/slurm/submit_robustness.sh` (the preset's M1 cells first, its M2 cells afterok; section 5). The M1c model of stage (b): `PRESET=context_b bash v2/slurm/submit_robustness.sh` (two M1 tasks, mid and fmid at lag 3; section 11). Simulations: `sbatch v2/slurm/05_simulations.sbatch` (open account). A timing pilot before setting the walltime of `02_main_grid.sbatch` (a 7-day placeholder), inside a job: `sbatch --account=open --time=04:00:00 --mem=64G --cpus-per-task=8 --wrap='source v2/slurm/00_env.sh && Rscript v2/R/02_fit_model.R --sample=mid --lag=5 --model=M2b --pilot=TRUE --threads_per_chain=8'` (1 chain × 60 iterations, saved as `fit_<cell>_pilot.rds`, which every production tool refuses); read "sampling finished in" from the log. Nothing in the repository submits jobs on its own.

The array index of `02_main_grid.sbatch` maps to (sample, model, lag) with lag slowest, then model, then sample: index = 24 × lag_index + 3 × model_index + sample_index, samples (mid, fmid, war), models (M1m, M1r, M1a, M1b, M2m, M2r, M2a, M2b), lags (1, 3, 5, 10). It is written out as an explicit case table in the script. Within-chain parallelism: `--threads_per_chain=k` (reduce_sum over state-years; `cpus-per-task = chains × k`, 8 threads and 32 cpus by default; the log density is identical across thread counts). Compiling M2 needs about 3 GB with `env/Makevars`.

## 3. The main specification

Defined once, in `R/spec.R` (the defaults of `SPEC_CHOICES` and the constants below it). Every switch at its default, cell names `<sample>_lag<h>_all_pr_<model>[_K2]`, e.g. `fmid_lag3_all_pr_M1b`, `war_lag3_all_pr_M2b_K2`.

| element | main specification |
|---|---|
| samples | `mid` (all MIDs), `fmid` (fatal, main coding), `war` (pair-level war); appendix samples `fmidcow`, `fmidub` can be fitted by hand |
| lags h | 1, 3, 5, 10 (change window [t − 1 − h, t − 1]) |
| choice set | every other system member at t with positions at t − 1, full sets (no sampling), the already-fighting states removed (two sets per state-year, section 6) |
| events | Side A × Side B pairs including joiners; war-level disputes follow COW's war initiator (`direction = cowwar`); escalations excluded; same-year duplicates collapsed |
| stage-2 weights | w_e = 1 / (the initiator's targets in the same dispute and onset year) |
| positions | M = log CINC share, R = log IGO PageRank; gaps divided by one constant per axis (3.268, 0.524) |
| changes | year-centred, pooled-SD scaled; raw (not winsorised) |
| **W** (stage 1, P1 = 8) | `dM_i`, `dR_i`, `M_lvl`, `R_lvl`, `ongoing_tm1`, `log_prior_mids`, `dem_tm1`, `log_n_system_tm1` |
| **X** (μ shifters, P = 2) | `dM_i`, `dR_i` |
| **Z** (dyadic, Pz = 7) | `contig_land`, `joint_dem`, `log_dy_prior_mids`, `dy_mid_tm1`, `dM_j_h`, `dRpr_j_h`, `dch_j_missing` (the last only when non-constant in the cell, which it is in every main cell) |
| centring | every W / X control except `dM_i`, `dR_i`, `M_lvl`, `R_lvl` is grand-centred (0/1 indicators included); the continuous Z columns are centred over the stage-1 IV rows; `dy_mid_tm1` and the indicators stay 0/1 |
| x_ref | mean X over the initiating state-years of the sample (`mu_state` is μ at x_ref) |
| M2 | K = 2 latent dimensions; anchors = the K states with most initiations |
| sampler | per family in `SAMPLER`: M1 4 chains × 2000 iterations (1000 warmup), adapt_delta 0.9; M2 4 chains × 4000 iterations (2000 warmup), adapt_delta 0.95 (PI decision 2026-10-25); max_treedepth 10; seed 123 |
| M2 inits | every M2 chain starts at the posterior means of the matching M1 fit (jittered), AME factors near 0; `--init_from=` names the fit, the default locates it in `output/`; no M1 fit → random inits, logged and recorded |
| typology | r0 = 0.5 scaled gap units |

Lag-3 dry runs of the main specification (6fd5362 and the restructured code, identical): S = 217, N1 = 14,597, N2 = 1,720,110 (1,719,835 IV rows, 1,719,990 stage-2 rows); mid E = 3258, sum(y1) = 2086, weights 2694.7; fmid E = 1055, 695, 741.0; war E = 432, 203, 222.6.

## 4. Switches

Every switch is an option of `02_fit_model.R`, `04_compare.R` and `05_robustness.R` as `--name=value`; the build takes `--direction` only. Every non-default value appends its suffix to the cell name in the order of `SPEC_SUFFIX` in `spec.R` (pairs, context, coal_ties, coal_drop, ww2, controls, distance, contiguity, major, interact, comparison, mu_shift, roles, joiner_set, weights, changes, direction, then the prior switches and the tag), so variants never overwrite main outputs: `war_lag3_all_pr_M2b_K2_noww2_sideA`, `fmid_lag3_all_pr_M1b_co_strict_drop3`, `mid_lag3_all_pr_M1b_major_ix`, `mid_lag3_all_pr_M1b_dist_major`, `mid_lag3_all_pr_M1b_dist_nocontig_major`. Defaults = the main specification.

| switch | values (default first) | effect | suffix | acts in |
|---|---|---|---|---|
| `pairs` | `all` / `originators` / `joiners` | event pairs kept: all; `is_joiner_pair` FALSE only; TRUE only. y1 is recomputed from the kept events exactly as `ww2 = drop` does, so a state-year whose only events were in the other group gets y1 = 0 (counts logged). Joiners-only is a **stage-2 comparison**: its stage 1 counts a state as initiating only when it joined. After the duplicate collapse `is_joiner_pair` is FALSE for a key with any originator pair. **D8 weights** (PI decision 2026-10-26): the filter can keep part of an (initiator, dispute, year) group (a dispute where the initiator faced originators and joiners), so in every group it splits the kept events' weights are divided by their kept sum, w_new = w / Σ w over the kept members, and the group sums to 1 again; groups kept whole keep the build's weights exactly (a group of collapsed keys that does not sum to 1 under `pairs = all` stays so). A collapsed key belongs to the group of its `dispnum` column (the smallest of its disputes), the only group it can have after the collapse, since its per-dispute weights are not recoverable. Applies with `weights = dispute` only; `ww2 = drop` and `coal_drop = top3` remove whole disputes and never rescale (asserted: a group is untouched or dropped whole, a split through a collapsed key kept by its other dispute is logged as a WARNING). ## 6. Data decisions

Flags of the build are at the top of `01_build_data.R`; the rules live in `helpers_data.R` and are unit-tested on toy disputes. Counts are from the rebuilt `data/build_log.txt`.

### 6.1 Events and joiners (PI decision 2026-10-24)

An event is a Side A participant → Side B participant pair of a COW-MID dispute, joiners included, with onset year equal to the first year that pair appears in the dispute (the sides are those of that earliest year; `build_pair_table()`, P3 fix 2026-10-25: France and the USSR are opposed in dispute 258 in 1939 and again with reversed sides in 1941, the only such pair), one direction per dispute pair, and every A × B pair of a multilateral dispute is an event. `INCLUDE_JOINERS = TRUE` is the main build (FALSE reproduces the originator-only base of 2770 events). With joiners there are 3720 events, of which 950 are joiner pairs (`is_joiner_pair`, TRUE when either side has `orig = 0`; kept for tabulation and for the `pairs` switch, never a covariate). The war sample grows most, from 127 originator pairs to 552 pairs, because the two world wars contribute most of their pairs through joiners. The fatal-MID rules apply unchanged to joiner pairs (with the pair-level war coding the joiner pairs are coded cow 897, mic_fill 50, uncoded 3; the war rule no longer adds any). The conflict-history controls count every participant including joiners (`INCLUDE_JOINERS` governs both).

### 6.2 Initiator direction (PI decision 2026-10-25, D1; the `direction` switch)

COW-MID Side A is the side that took the FIRST codable action, not the aggressor. In dispute 258 (the Second World War) Side A is Poland and the Allies, so the Side A rule produced Poland → Germany, UK → Germany and USA → Germany in 1939–41 and never Germany → Poland. For wars the standard aggressor coding is COW's war initiator, so for disputes at hostility level 5 that can be linked to a COW inter-state war (`cow_war_inter`, which has the war sides `sidea1 / sidea2` and the state-level initiator flags; every COW war has exactly one initiating side, asserted) the direction follows COW's war-initiating side. The rule has two steps. (a) Pair level. A MID pair (i, j) with onset year t is matched to the COW war dyad-years (i, j) in t or t + 1 (`WAR_DIR_WINDOW = 1`; MID onsets precede war onsets, the crisis year is often the year before the fighting reached war level). Every matched row votes: reverse when j's war side initiated, keep when i's did; unanimous votes decide the pair (`dir_source = "cow_war_pair"`, whether reversed or confirmed), mixed votes (two wars with opposite initiators) leave Side A. On the data 363 of the 552 war-level pair events match (310 at t, 53 at t + 1 only; t + 2 would add 5, any later ongoing year 29, not used); 160 are reversed, 201 confirmed, 2 ambiguous (dispute 611 / 1360, Vietnam–Cambodia, matched to wars 163 and 176). (b) Dispute level. The unmatched pairs of a war-level dispute follow the dispute's side mapping when it is unambiguous: the dispute is linked to the COW war that a strict majority of its pair-decided events matched, at least `WAR_DIR_MIN_LINK = 2` of them; the war side of the MID Side A state over those events must again be a strict majority of at least 2; if that side is the war's non-initiating side the unmatched pairs are reversed (`"cow_war_dispute"`), else kept. 34 disputes are linked with an unambiguous mapping (no dispute had a split mapping); 32 unmatched pairs are reversed and 93 kept. Everything else keeps Side A (`dir_source = "sideA"`): the 3168 events of non-war disputes, 14 events of 4 war-level disputes with no pair match, 50 events of 18 disputes whose link rests on a single pair-decided event (below the minimum; with a minimum of 1 they would be 2 reversals and 48 confirmations, logged, not applied) and the 2 ambiguous pairs. In total 192 of 3720 events (35% of the war-level pairs) are reversed in 24 disputes, 160 by the pair match and 32 by the dispute mapping; the originator status, fatality and hostility codes move with the state, so `is_joiner_pair`, `war` and the fatal codings are unchanged. `events.rds` carries `dir_flipped`, `dir_source`, `dir_rule` (the reason), `war_link` (the COW war number) and `n_war_match`; `sidea1 = 0` marks a reversed row. Everything downstream (escalation flags, reference dates, choice sets, `fighting_at_ref`, the duplicate collapse, y1, the no-WWII flags, the event weights) is computed from the applied direction in every sample; no collapsed key mixes a reversed and an unreversed source. The build stops unless Germany → Poland 1939 exists and Poland → Germany 1939 does not. The appendix rebuild `Rscript v2/R/01_build_data.R --direction=sideA` applies the old coding everywhere and writes to `v2/data_sideA/` (its own manifest and build_log), so the two codings never overwrite each other; `--direction=sideA` in the fit, compare and robustness scripts reads that directory and suffixes the cells with `_sideA`.

### 6.3 Participant-level dates (PI decision 2026-10-25, D5)

peacesciencer 1.2.0 bundles `gml_part`, participant-level start and end year / month / day (the day is unknown for about 10%) for 2165 of the 2436 COW dispnums (5217 participant spells). Where the dispnum matches, `pair_dispute_intervals(part = gml_part)` dates a pair spell from its participants: entry = the later of the two participants' starts, exit = the earlier of their ends, both exact months, when each participant has exactly one gml_part spell overlapping the pair's COW years and the dates are consistent with those years (a GML entry before the pair's first COW year is clamped to January of it, since the pair was in the dispute by then; a GML exit after the last COW year to December of it; an entry after the first COW year or an exit before the last one contradicts the COW years and keeps the dispute-level bounds, as do participants with no or several overlapping spells). 5874 of the 7456 directed spells are dated this way (5634 directly, 84 with the entry clamped, 152 with the exit clamped, 4 both); 1582 keep the dispute-level bounds (774 in disputes absent from gml_part, 350 with a participant lacking an overlapping spell, 132 with several, 326 inconsistent years or entry after exit; `date_source` and `part_reason` in the interval table, counts in the build log). An unknown entry bound is also clipped by the feasible exit (688 directed spells had start_hi > end_hi under the dispute-level bounds; 216 still needed the clip after the participant dates). Before / after (dispute-level bounds / participant dates): exact entry months 5536 / 6846 and exact exit months 486 / 5988 of 7456 spells; escalations 199 / 215 (38 new, 22 dropped); undecided (event, other dispute) comparisons 230 / 71; events whose decision rests on a year-rule fallback 184 / 64; `fighting_at_ref` events 31 / 28; already-fighting (i, j, t) keys at the reference date 3687 / 3669; same-year opposite-direction pairs among the non-escalation events (both i → j and j → i in t) 118 / 113. ### 6.4 Escalation and the already-fighting rules (PI decisions 2026-10-24, month resolution)

Stage 2 is target selection, so a new dispute against a state the initiator is already fighting is escalation, not selection. An event is an escalation when i and j are both participants in a different dispute that started before the event's dispute start date and had not ended by it, compared at month resolution. The year-level version of this rule (pair in a dispute active in year t with onset before t) mislabelled about 45% of the escalations (China → USA 1950, the Korean War, was dropped because a short 1949 incident had a 1950 row) and missed re-entries within a year. The fallback dates come from `cow_mid_disps` and are dispute-level, because that table ships the dispute start month and year (`stmon`, `styear`) and the duration in days (`mindur`, `maxdur`) but no end month and no participant-level dates (`cow_mid_dirdisps` has years only); participant-level months come from `gml_part` where available (6.3). The end date is therefore a bound, not a point, between the first day of the start month plus `mindur` and the last day of the start month plus `maxdur`, clamped to the dispute's last year in the directed dispute-years (198 of 2436 disputes have an exact end month, 1954 a two-month span, 284 wider, 10 inconsistent with the duration and given the whole last year). A pair that enters a dispute after its first year has an unknown entry month (the whole year), a pair that leaves before the dispute's last year an unknown exit month, and a pair that leaves and re-enters has separate spells. Every comparison is three-valued. When it is undecided the year rule decides and the fallback is counted. Escalations stay in `events.rds` with `escalation = TRUE` (`escalation_year` keeps the year rule, `esc_fallback` marks fallback decisions, `ev_start_lo` / `ev_start_hi` the event's date interval as a month index) and are excluded from every sample flag, so they are in neither stage 2 nor y1. Result with the participant dates: 215 escalations.

Joiner entry month (Codex review P1-2, 2026-10-24). A pair with a joiner on either side (`orig == 0`) whose spell begins in the dispute's first year used to receive the dispute's exact start month although the joiner's entry month is unknown. Its entry interval is [dispute start month, December of that year] with `start_exact = FALSE`; originator pairs keep the exact start, later entrants keep the whole entry year. On the COW data 1154 of 7456 directed spells (577 undirected pairs) are affected; escalations fell from 217 to 199 under the dispute-level bounds. The build rebuilds the pre-review intervals only to log these before / after counts.

Two choice sets per state-year (Codex review P1-1, PI choice "A′", 2026-10-24). C_n^{iv}, the stage-1 IV set, drops alternative j when i and j are in a dispute active at January of t that started before it, for every state-year alike, so the stage-1 regressor IV_n uses no information about the state-year's own events (the previous rule used the event date for initiators and January for non-initiators, which made the IV set a function of y1). C_n^{s2}, the stage-2 set, drops j when i and j are in a different dispute active at the state-year's reference date, the start of its earliest non-escalation event when it initiates and January of t otherwise, that started before it. Both rules are the month rule with the year fallback, and nothing after the respective date enters. For a non-initiating state-year the two sets are identical. The alternatives files keep one row block per state-year, the union of both sets, with the flags `in_iv` and `in_s2` (`choice_set_flags()`); rows in neither set are removed; the Stan programs sum IV over the `in_iv` rows and run the softmax over the `in_s2` rows. At h = 3, 1,720,110 rows remain (1,719,835 IV rows, 1,719,990 stage-2 rows). Because the stage-2 set is fixed at the reference date, a later event of the same state-year whose pair was still fighting at that date (their dispute ended between the reference date and the event) has no stage-2 row (it may keep an IV-only row with `in_s2 = 0`). There are 28 such events (7 fmid, 1 war), flagged `fighting_at_ref`. They keep every sample flag, so y1 is unchanged, and leave stage 2 only, like events whose target lacks positions; the build lists them and stops if any other non-escalation event loses its stage-2 row. This is a deviation from the requirement that every non-escalation event's chosen alternative be in its choice set, which cannot hold with one stage-2 set per state-year, and is flagged for the PI. The build asserts that the IV flag equals the January rule on every retained row and that only initiating state-years have differing sets, and stops if any state-year with rows has an empty IV set or any initiating state-year a stage-2 set that is empty or holds only its chosen target (`assemble_cell()`, `build_stan_data()` and the Stan programs repeat these checks). Helpers `dispute_date_bounds()`, `pair_dispute_intervals()`, `month_rule()`, `flag_escalations_month()`, `reference_dates()`, `already_fighting_keys_month()` (reference `NULL` = January for every state-year).

Same-year duplicates (PI decision 2026-10-24). After the escalation exclusion, events with the same (initiator, target, year) from different disputes collapse into one event (`collapse_duplicate_events()`). Sample flags and fatality codings are ORed, `dispnum` keeps the smallest dispute number, `dispnums` lists them all, `n_disputes` counts them, `is_joiner_pair` is FALSE when any collapsed row was an originator pair, the per-sample weights are summed and capped at 1, and escalation rows are untouched. One chosen alternative per (i, j, t) is asserted in the build and in `assemble_cell()`. The no-WWII sample flags `in_<sample>_noww2` (Codex review P2-3) are the sample flags of the non-WWII source rows alone, ORed in the same collapse, so a key that mixes a WWII and a non-WWII dispute stays in the `ww2 = drop` sample only when a non-WWII dispute qualifies (UK → Bulgaria 1941, disputes 258 and 3871, stays in the no-WWII `mid` sample and leaves the no-WWII `fmid` and `war` samples; the other five collapsed WWII keys are WWII-only).

WWII (`ww2 = drop`). `is_ww2` marks the events of 16 COW-MID disputes, 258 (the Second World War itself) plus every war-level dispute that starts between 1939-09 and 1945-09, whose highest action is 21 (join interstate war) and whose dyad appears in COW inter-state war 139 in `cow_war_inter` (235, 339, 414, 418, 518, 2725, 3701, 3705, 3717, 3724, 3813, 3820, 3822, 3826, 3827, the run-ups to a state's entry into the war). Disputes 157, 179, 183 and 613 are wars of their own (COW wars 130, 142, 136, 145) and stay. The rule is `ww2_disputes()` in `helpers_data.R`, the list is asserted against `WW2_DISPNUMS`, and the build log prints every candidate with its reason. 134 of the war events are WWII; `ww2 = drop` removes them from stage 2 and their initiations from stage 1 using the `in_<sample>_noww2` flags, so a state-year whose only events were WWII gets y1 = 0.

Lagged involvement at t − 1 (PI decision 2026-10-24), always from every participant including joiners. `ongoing_tm1` (stage 1) is 1 when the state was in any MID active in year t − 1 (mean 0.31 at h = 3). `dy_mid_tm1` (stage 2) is 1 when i and j were both in a MID active in t − 1; `assemble_cell()` stops if it is constant in a cell.

### 6.5 Fatal and war coding

Samples: `mid` (all), `fmid` (fatal, main coding), `fmidcow` (fatal, COW-only coding; appendix), `fmidub` (fatal, upper bound; appendix), `war` (pair-level war). The interacting-dyads build (`--events=dymid`, section 6.9) has its own dyadic codings of `fmid`, `fmidany`, `fmidub` and `war`.

* War is coded at the pair level (PI decision 2026-10-24, revised the same day). An event is a war event only when the dispute is war-level (hostility level 5) and at least one participant of the pair reached hostility level 5 itself (participant `hostlev1` / `hostlev2` in `cow_mid_dirdisps`, maximum over the pair's years). The dispute-level coding is kept as `war_disp`. Of the 552 dispute-level war pairs 508 are war pairs (44 had neither participant at level 5, mostly peripheral Gulf War and Iraq 2003 coalition members). A first version required both participants at level 5 (329 events); the PI chose the less strict rule. The war rule in the fatal coding uses the pair-level definition.
* COW fatality: an event is fatal if either side's fatality ≥ 1 or the dispute fatality ≥ 1; negative codes → missing. 229 of 2,770 originator events have every COW fatality code missing.
* `fmid` (PI decision 2026-10-23) applies four rules in order. (a) Wars are fatal by definition, since COW wars require 1,000+ battle deaths. (b) A coded COW fatality value is kept as is. (c) When every COW code is missing, the event takes the MIC 1.0 value (Gibler et al., Militarized Interstate Confrontations; confrontation-level `fatalmin` ≥ 1; MIC `micnum` = COW `dispnum`; `data_raw/mic-conf-1.0.csv`, sha256-checked against `MIC_CONF_SHA256`, see `data_raw/SOURCE.md`). (d) When COW and MIC are both missing, the event takes the GML MID 2.2.1 coding of the same directed pair (peacesciencer `gml_mid_ddydisps`; same rule as COW). No source overrides an earlier coded value. Where both COW and MIC code fatality they disagree on 120 events, logged, not used. `fatal_source` in `events.rds` records which rule set each event.
* `fmidcow` is the earlier rule (missing → not fatal, no war rule). `fmidub` is the bounds check, `fmid` plus the events no source codes, counted as fatal; if `fmid` and `fmidub` agree, the uncoded events do not drive the fatal-MID findings.

Events after the collapse: mid 3417, fmid 1144, fmidcow 979, fmidub 1162, war 464. Stage-1 initiations at h = 3: mid 2086, fmid 695, war 203.

### 6.6 Positions and changes (PI decisions 2026-10-23)

Positions. M = log CINC share and R = log IGO PageRank, both left in raw log units. CINC share and PageRank each sum to one over the system in a year, so M is the log share of world capabilities and R the log share of network centrality, and the stage-2 gaps x_ij = (M_i − M_j, R_i − R_j) are log ratios between the two states. The two axes have very different spreads (SD about 3.27 log points for M and 0.52 for R), so each gap is divided by one constant per axis, the same for every year and lag: the SD of the within-year gap over all ordered pairs of distinct states (`gap_scale()`), 3.268 for M and 0.524 for R, stored in `change_scale.csv` with h = NA; the raw log ratios are kept as `dM_logratio` and `dR_pr_logratio`. One model unit on the material axis is therefore a 26-fold ratio of CINC shares, and on the relational axis a 1.7-fold ratio of PageRank. No script converts estimates back; multiply a μ, Σ or r0 value by the constant for its axis by hand. The build stops and lists any state-year with a zero or missing CINC share or a non-finite or non-positive PageRank (none exist). PageRank weights are shared IGO memberships with isolates included as vertices. Years with all-missing IGO data are dropped (`IGO_FILL = "drop"`; none with peacesciencer 1.2.0; 1990 is partially missing and its NA dyads are treated as no shared membership). Why: on within-year z-scores a state's change moved with the growth of the system (correlation with the 3-year log growth in the number of states about +0.29 for M and +0.17 for R at h = 3) and the changes had SD 0.11 and 0.25, so the per-unit priors dominated.

Changes. One state-level table per lag, `changes_lag{h}.rds` (`build_change_table()`). For every state in the system at t with positions at t − 1 and t − 1 − h, the raw change is level(t − 1) − level(t − 1 − h) in log units (calendar joins, never row lags; `dM_raw_h`, `dRpr_raw_h`). The transformed change `dM_h`, `dRpr_h` subtracts the mean raw change of all states that have a change in that year and divides by one pooled constant per lag and variable, the SD of the year-centred change over all rows of that lag (1 unit = 0.19 log points for M and 0.15 for R at h = 3; constants in `change_scale.csv`). Zero means the state changed like the average state over the same window. The same table supplies the initiator's change in stage 1 (`dM_i`, `dR_i` in W and X) and the target's change in stage 2 (`dM_j_h`, `dRpr_j_h` in Z for every model). A target with no change value (typically a recent entrant) gets 0 and `dch_j_missing = 1` (62k of 1.72 million rows at h = 3). The build asserts finiteness, within-year mean 0, pooled SD 1 and |cor| < 0.02 with the system-growth variable.

Power levels in stage 1 (PI decision 2026-10-25, D2 and D3). `M_lvl` and `R_lvl` are the within-year centred log CINC share and log PageRank at t − 1 (centred over every state with positions in that year) divided by the gap constants, so their units match the gap axes (0 = the system-average level that year); they enter W, not X (levels in X are an open PI question). `log_n_system_tm1` (centred log system size at t − 1) is in W because the IV grows with the number of alternatives (`assemble_cell()` logs cor(IV at a null point, log n) = 0.856 and the R² of that IV on W without / with the column, 0.091 / 0.767 at lag 3).

Timing: positions at t − 1; changes over [t − 1 − h, t − 1]; dyadic controls (contiguity, ATOP alliance, joint democracy polity2 ≥ 6, major-power count) at t − 1; all via calendar joins. Conflict history: monadic and dyadic MID onset counts in the 10 years before the window starts (`log1p()`, centred), peace years as of the window start (full control set only). Democracy and alliance NA → 0 with `*_missing` indicator columns in the data. Panel 1816–2014 (COW-MID 5.0 end); state index = all states appearing as initiators or targets (S = 217).

### 6.7 Coalition weights (PI decision 2026-10-25, D8; the `weights` switch)

Every A × B pair of a multilateral dispute is an event, so an initiator joining a dispute against k Side-B members contributed k softmax terms. The stage-2 part of the log density is a composite likelihood with dispute-level weighting: event e enters as w_e · log P(j_e | n_e) with w_e = 1 / (the number of distinct targets the same initiator has in the same dispute and onset year, counted within the sample), so such an initiator-dispute-year contributes one decision's weight while targets in different disputes stay separate decisions. The build writes `w_mid`, `w_fmid`, `w_fmidcow`, `w_fmidub`, `w_war` on the pre-collapse rows (`event_weights()`), 0 outside the sample; the collapse sums a key's weights and caps at 1 (72 mid keys hit the cap). On the data (mid, before the collapse) 3517 events in 2883 initiator-dispute-years have weights summing to 2883; minimum 1/37 (Yugoslavia → the 37 KFOR states in dispute 4343, 2000); in dispute 4186 (2000) the 38 KFOR states are each a Side A initiator against Yugoslavia alone, so their events keep weight 1. `build_stan_data()` passes the weights as `ev_w` (1 everywhere when absent); both Stan programs multiply the stage-2 log-lik terms by `ev_w`; with every weight 1 the log density equals the unweighted program (asserted against the dd48506 binaries). `log_lik_stage2` stays the unweighted per-event term. The joint state-year LOO and the permutation statistic use the weights; the stage-2-only LOO does not. Events that leave stage 2 (`fighting_at_ref`, target without positions) do not rescale their group's remaining weights (logged).

### 6.8 Joiner entry direction (PI decision 2026-11-04; the `entry` switch)

**Rule.** In the main build a MID event is a Side A × Side B pair directed from Side A (after the D1 war flips), so a state that joins the DEFENDING side appears only as a target: the UK, entering dispute 258 in 1939 for Poland, is coded Germany → UK. The PI's decision is that a joiner makes an initiation choice against the side it joins against, whichever side that is. Under `entry = later`, for every pair of opposing participants in a dispute: (a) both COW originators: the main direction, unchanged; (b) exactly one joiner (orig = 0): the JOINER is the initiator and the originator the target, so an originator → late-entrant pair (the former "target joined late" events) is REVERSED, not duplicated; (c) two joiners: the later entrant initiates, entry being the participant's entry date of its spell covering the pair's onset year (`participant_spell_dates()`, the GML day or month where known, else the dispute bounds; the two dates compared at the coarser of their resolutions, the D5 convention); an exact tie keeps the main direction. A joiner's targets are therefore all opposing-side states active in the dispute in its entry year (the PI chose "all attacking-side states"), one event each, weighted 1/n within (initiator, dispute, onset year) like every multi-target decision (D8). Implemented by `entry_later_direction()` in `helpers_data.R`, applied right after the D1 direction step in `01_build_data.R`, so the escalation and already-fighting rules (month resolution, the event's own date), the sample flags, y1, the weights, the duplicate collapse, the coalition flags, the roles and the joiner sets are all recomputed from the new events. The conflict-history controls (monadic and dyadic prior MIDs, peace years, `ongoing_tm1`, `dy_mid_tm1`) are built from the raw COW directed dispute-years, not from the events, so their definition does not change. Under `later` no late-target event exists (asserted), which is why the codings `bc` / `bcj` need it.

**Checks and counts.** The build asserts UK → Germany 1939 exists and Germany → UK 1939 does not (verified on the keep data first: Germany, an originator, → UK, a joiner, dispute 258), and Germany → Poland 1939 still exists. Pre-collapse directed events 3720: both originators 2770 (unchanged), one joiner 668, two joiners ordered by entry 221, ties 61 (unchanged); reversed 420 (all 324 former late-target events, and 96 joiner → later-joiner pairs). Collapsed non-escalation events, keep → later: mid 3417 → 3424 (3065 identical, 359 reversed, none added or removed beyond reversals; the count grows because seven keys no longer collapse), fmid 1144 → 1154 (911 identical, 243 reversed), war 464 → 472 (299, 173). Lag-3 initiating state-years: mid 2086 → 2223 (160 new, 23 lost), fmid 695 → 813 (146 new, 28 lost), war 203 → 298 (114 new, 19 lost). Aprime groups after the collapse: alone 2305, co-originator 244, joiner 875, target late 0. Lag-3 directed usable events under `later` (fmid / mid): E = 1080 / 3276, sum(y1) = 813 / 2223, weights 870.0 / 2907.0; `bcj`: bilateral 503 / 2198 (weights 490.1 / 2070.2), coalition originator 36 / 232, joiner 541 / 846 (343.8 / 616.3); `bc`: bilateral as above, coalition 577 / 1078. With `--joiner_set=opposing` the 541 / 846 joiner events have restricted sets of median size 2 / 1.5 (max 23), 188 / 423 of size 1.

### 6.9 Interacting dyads (PI-approved 2026-11-04; the `events` switch)

**Why.** The main events pair every Side A participant of a MID with every Side B participant. A multilateral dispute therefore creates pairs that never interacted (USA – Finland in the Second World War: COW lists both in dispute 258 on opposite sides in 1941-44, so the pairs build has Finland → USA 1941 as a `mid`, `fmid` and `war` event, while no USA – Finland dyad exists in Dyadic MID or the war data, so no such event exists under `dymid`; correction of 2026-11-08: an earlier text gave Japan – Poland, which is in NEITHER build, since Poland's COW participation in 258 ends in 1939 and Japan's begins in 1941), and the fatal coding counts a pair fatal when either state or the dispute had deaths, so coalition pairs are fatal by association. Morocco – Iraq in the 1990 Gulf dispute (3957) is an example of the second problem only: it IS an interacting DYMID dyad (a display of force, `hihost` 3, no deaths on either side), so it remains a `mid` event under `dymid` (Morocco → Iraq 1990, decided by rule (a): Morocco joined against the originator Iraq), and only the strict fatal rule removes it from `fmid` (the pairs build has Iraq → Morocco 1990 in `fmid`). `--events=dymid` rebuilds every data file on the dyads that interacted directly, from Maoz's Dyadic MID 4.03 and the Directed Dyadic Interstate War data (`data_raw/dymid/`, provenance and checksums in `data_raw/SOURCE.md`), into `v2/data_dymid` (own manifest and `build_log.txt`; `Rscript v2/R/01_build_data.R --events=dymid` or `V2_EVENTS=dymid`, about 3 minutes). Functions in `R/helpers_dymid.R`, each unit-tested on hand-built rows (`test_dymid.R`).

**Event unit and dates.** Dyadic MID 4.03 lists every directed dyad-year of a dyadic dispute in both directions. Its `dyindex` is an integer equal to `disno` on every row (the decimal dyad suffix of version 4.01 was lost), so it cannot identify a dyad: the build keys a dyadic dispute by (disno, unordered pair), 3,511 dyadic disputes in 2,371 disputes. One event per dyadic dispute; its onset year and date are the dyad's OWN first start (`strtyr`, `strtmnth`; dyad-level, not dispute-level dates). A pair that re-enters the same dispute (several start months; separate dyindices in 4.01) stays ONE event dated by its first spell: 25 pairs, 18 of them in the two world wars (listed in the build log). This mirrors the pairs build, where a pair's onset is its first year in the dispute, and keeps (dispute, pair) unique; the later spells enter the already-fighting rule as spells of that pair. **Re-entry spells (fix of 2026-11-08).** The pair-dispute spells (`pair_dispute_intervals()`) are runs of consecutive participation years, and `dymid_override_pdi()` dated each run by the earliest start and the latest end among the dyad's years, which BRIDGED a dyad that left the dispute and re-entered it in a later year: USA – Bulgaria in 258 (Dec 1941 – Jun 1942 and Nov 1943 – Apr 1944) was one spell Dec 1941 – Apr 1944, so the pair counted as already fighting at January 1943 and left the 1943 choice sets. Now every DYMID spell (distinct start month within the dyad-dispute, with its own latest end and years; attr `spells` of `dymid_link()`) is its own pair-dispute spell, renumbered in date order (spell 1 = the event's date, so the onset and the escalation comparison of the event itself are unchanged), and the already-fighting rule, the choice-set reference dates and the escalation comparisons against other disputes see the gap; spells of one dyad may share a year (a pair leaving and re-entering within a year, 8 dyad-years), handled as the spells of a pair already are (any()). The entry rule (a) reads participant-level spells (a state's consecutive years in the dispute), which a dyad re-entry does not bridge, so no direction changes. Effect: 14 undirected (28 directed) pairs split, 38 spell rows added (7,602 → 7,640 directed spells; the build asserts the USA – Bulgaria example and that the union of years per pair is unchanged); no event changes its date, escalation flag, `fighting_at_ref` or sample; already-fighting directed (i, j, t) keys at the reference date 3,369 → 3,336 and at January 3,518 → 3,490, i.e. 33 (stage-2) / 28 (IV) directed pair-years return to the lag-3 choice sets, among them USA – Bulgaria 1943 in both directions, USA – Romania 1943-44, Canada – Germany 1943, Belgium – Germany 1940, Japan – New Zealand 1941, the WWI re-entries of 257 (USA – Austria-Hungary 1917-18, Italy – Turkey 1915-16, Bulgaria – Russia 1916, Bulgaria – Romania 1914-15, ...) and Syria – Israel 1994, 1995, 2000 (4182).

**The two directed copies and the adjudication table (fix of 2026-11-08).** Dyadic MID lists every dyad-year twice, (A, B) and (B, A), and the build used the A < B copy as if the two agreed. They do not always: at the dyad level (the fields the build aggregates and uses, `DYMID_COPY_FIELDS`: start and end month, the three fatality codes, the war flag, the dyadic initiator, the originator flags, `recip`, the three hostility levels, the sides) 29 of the 3,511 dyadic disputes disagree on 57 fields. Direction-relevant initiator codes, 8 dyads: the two rows carry the same `dyad_rolea` instead of mirrored ones, so each copy names a different initiator; in 6 dyads both rows have `dyad_rolea` = 1 (each copy names its own state A), Norway – Denmark 1981 (2970), UK – Bulgaria 1941 (258), North – South Korea 1993-99 (4022), 2882, 3012 220 – 540, 3858; in 2 dyads both rows have `dyad_rolea` = 3 (each copy names its own state B), Uruguay – UK 1939 (3833) and 3012 540 – 600. ## 7. Model

Stage 1 (state-year n, state i): `y1 ~ Bernoulli(logit⁻¹(α0 + W'α + c_i + τ·IV))`. Stage 2 (event e by state-year n):

```
U_ij = −½ (x_ij − μ_n)' Σ⁻¹ (x_ij − μ_n) + b_j + z_ij'γ [+ u_i'v_j in M2]
x_ij = (M_i − M_j, R_i − R_j) at t−1 (scaled)      μ_n = μ0 + X_n β + a_i   (μ0 is 1 × D, β is P × D)
P(j | n) = softmax over C_n^{s2}                     IV_n = log Σ_{j∈C_n^{iv}} exp U_ij
log density = Σ_n log Bernoulli(y1_n) + Σ_e w_e log P(j_e | n_e) + priors
(c_i, a_i1, a_i2) ~ MVN(0, Ω)                        b_j ~ N(0, σ_b) (soft sum-to-zero)
```

μ0 is the intercept of the ideal target position (PI-approved 2026-10-23). Because x is the initiator-minus-target gap, μ0 is the population-average preferred gap, the paper's central quantity (bully > 0, peer ≈ 0, challenger < 0). In the main specification X holds only the two power changes, so μ0 is the ideal gap of a state with zero power change; every W control is centred, so α0 is the stage-1 log-odds at zero power change and average controls. `mu_state` at `x_ref` = μ0 + x_ref'β + a_i.

Identification and priors. Only Σ⁻¹ and Σ⁻¹μ are identified by the choice data; μ is recovered as Σ(Σ⁻¹μ) automatically. The "a" models fix corr(a_i1, a_i2) = 0 but keep corr(c, a_1) and corr(c, a_2), parameterised so Ω is always PD (r2 = q·√(1 − r1²)). AME: V and U column-centred (the translation U[,k] + h, b_j − h·V[j,k] is removed), the anchor block of U (K states with most initiations) lower-triangular with positive diagonal, U/V scale fixed by N(0, 1) priors; Procrustes alignment across chains in `03_extract.R` is a safety net whose rotation deviation is logged. Priors: μ0 ~ N(0, 2) per element (`prior_mu0_sd`, data), β ~ N(0, 1) (`prior_beta_sd`), σ_x ~ lognormal(0, 1), sd of random effects ~ half-N(0, 1), LKJ(2) on the 3×3 correlation of (c, a_1, a_2) in the b models and its restriction to corr(a_1, a_2) = 0 (the disk density ∝ 1 − r_1² − r_2², exact Beta(2.5, 2.5) marginals; review fix 2026-10-25, B4) in the a models, (ρ + 1)/2 ~ Beta(2.5, 2.5) on Σ's correlation, (r + 1)/2 ~ Beta(2.5, 2.5) on corr(c, a) in the one-dimensional models, γ, α, τ ~ N(0, 1), α0 ~ N(0, 2.5). The correlations shared across models carry the same prior, so m / r / a / b differ only by their restrictions (prior-only runs in `tests/testthat/test_priors_a_vs_b.R`). Prior sensitivity (2026-10-30): the `rho_prior` and `sigma_prior` switches of section 4 replace the Beta(2.5, 2.5) on (ρ + 1)/2 by Beta(1, 1) and the lognormal(0, 1) on σ_x by lognormal(0, 0.5), through `stan/m1_latent_prior.stan`, which is the M1 program with those two hyperparameters as data (`prior_rho_shape`, `prior_sigma_x_sd`; the two sources differ in exactly those lines, asserted in `test_tag_prior.R`); the main program is not edited, so the hashes of the existing fits stay valid.

M2 initial values (PI decision 2026-10-25). Every M2 chain starts at the posterior means of the matching M1 fit, M2m from M1m, M2r from M1r, M2a from M1a, M2b from M1b, same sample, lag and switches whatever the M2 fit's K (`locate_m1_fit()` through `m1_spec()`, so `--ame_K=1` and `--ame_K=3` start from the same M1 fit; or `--init_from=`). `m1_inits_for_m2()` (`helpers_model.R`; it logs a line whenever a correlation init has to be clamped to ±0.95) copies every parameter the two programs share with identical dimensions (α0, α, τ, μ0, β, γ, σ_x, the random-effect scales and correlations of the model's variant, and the standard-normal random effects z_re / z_b, which the saved M1 fit does not hold and which are reconstructed from the saved c_i, a_i, b_j, sd_re, σ_b and R_Om), draws the AME factors u_diag, u_lower, U_free, V_raw uniformly on `INIT_UV_RANGE` = (−0.1, 0.1) (u_diag on its positive upper half) with seed 123 + chain, and jitters each chain by N(0, `INIT_JITTER_SD` = 0.05) on the unconstrained parameters (multiplicatively on the scales, N(0, 0.01) on the correlations, kept PD), so the chains differ and R-hat stays meaningful. The M1 fit must be a production fit of the current data that scores exactly the cell (`assert_production_fit()`, `assert_fit_current()`, `assert_fit_matches_cell()`, all in `helpers_model.R`) with the same `D_mode` and `joint`. When the default lookup finds no M1 fit FILE the run falls back to Stan's random inits and says so in the log, in `obj$init` / `obj$args$init_source` and in the `init_source` / `init_from` columns of `summary_<cell>.csv`; an M1 file that exists but fails a check is an error, auto-located or named with `--init_from` (audit fix 2026-10-26; before, every rejection fell back silently). No prior or constraint of M2 changed. Tested on tiny synthetic M1 and M2 fits (`tests/testthat/test_m2_inits.R`: names and dimensions against the M2 program, a Fixed_param draw at the init reproduces the M1 means, factors within (−0.1, 0.1)) and end to end on the toy cell (`test_fit_smoke.R`: `02_fit_model.R` M1b then M2b with `init_source = m1_posterior_means`, the unusable-file cases exit non-zero, the no-file case falls back loudly).

Both programs evaluate the likelihood as `reduce_sum_static` over state-years (`grainsize` is data; one slice = the exact serial sum). Generated quantities: `log_lik_stage1[N1]`, `log_lik_stage2[E]`, `mu_state[S, D]` (at `x_ref`), `mu_event[E, D]`, `Sigma`, `Omega`, `R_Om`. The programs reject an empty IV set, a chosen row outside the stage-2 set, a stage-2 set that is empty or chosen-only, and a row in neither set.

Fit provenance and safety. `02_fit_model.R` reads `manifest.csv` and `git rev-parse HEAD` before assembling, passes the manifest snapshot into `assemble_cell()` (every input file's nrow and sha256 are checked against it), re-reads the manifest before saving and saves the fit as `fit_<cell>_STALE.rds` if any digest changed while sampling (downstream tools need `--allow_stale`). The compiled program must be the checked-out source (`assert_compiled_current()`: model_code identity plus the `.sha256` sidecar written by `compile_models.R`). Fits are written atomically (`.rds.tmp`, read back, renamed). Before saving, the stanfit must hold every requested chain with all its post-warmup draws (`assert_fit_chains()`; with parallel chains rstan drops a failed chain, e.g. a rejected init, and returns the survivors with mode 0, so a 3-of-4-chain fit would otherwise have been saved as production and released the afterok dependents); the run stops with a non-zero exit and writes nothing otherwise, and `assert_production_fit()` repeats the check downstream. Pilots (`--pilot=TRUE`) are saved with `_pilot` and refused by every production tool (`assert_production_fit()`); `03_extract.R`, `04_compare.R`, `05_robustness.R` (perm_error) and `06_context_compare.R` refuse a fit whose stored data digests differ from the current manifest (`assert_fit_current()`) and a fit whose recorded Stan source hash differs from the compiled program's sidecar `stan/build/<family>.sha256` or from the hash of the checked-out `stan/<family>.stan` (`assert_fit_stan_current()` requires source = sidecar = fit; fits of two programs can never be mixed in one `output/`, so deploy into a fresh clone or an empty `v2/output/`), and the robustness tests check that the fits score exactly the assembled cell (`assert_fit_matches_cell()`). The program a fit is checked against is derived from its model code and its saved switches (`stan_program(model, spec)`: `m1_latent_prior` for an M1 fit with `rho_prior` / `sigma_prior` off their defaults, the main program otherwise, also for every fit saved before 2026-10-30), and a fit whose recorded `args$stan_program` disagrees with that is refused as well. Adding `m1_latent_prior.stan` changed no existing program, so a clone at this commit reads every fit of the previous commits unchanged; only the new program must be compiled once (`Rscript v2/R/compile_models.R` in a job compiles it and leaves the three cached ones alone).

## 10. Context split (dual typology stage a)

PI-approved spec of 2026-10-25, stage a of the dual typology: do states target differently when they act alone and when they act in a coalition? The answer is read off two refits of the same cell with the stage-2 events split by the coalition context of their D8 group; nothing changes in the Stan programs.

**The flag.** Context = the dispute has more than one state on either side at the onset. The unit is the D8 weight group (initiator, dispute, onset year), so that the `context` switch keeps or drops a group whole and the weights w_e stay a partition of one decision per group. The flag is evaluated once per group at the **group onset**, the earliest pair onset among the initiator's pairs of that dispute-year (the date the initiator first faced an opponent in that dispute-year), and is constant within the group by construction (asserted in the build and at assembly). Evaluating every pair at its own onset instead would give different flags inside 72 (inclusive) / 96 (strict) of the 2874 groups of the COW data, e.g. Germany in dispute 258, 1939: the Poland pair starts 1939-03-25 with no third state present, the UK and France pairs 1939-03-31 with Poland present. The build logs that per-event heterogeneity as a diagnostic (`build_log.txt`, "DIAGNOSTIC") and does not use it; whether the group-level reading is the one the PI wants is flagged for decision.

**Dates.** Participant entry and exit dates come from `gml_part` (D5) where the dispnum and the participant match and the GML years agree with the COW years: day resolution when `stday` / `endday` are known, month otherwise; a GML entry before the first COW year is clamped to January of it, a GML exit after the last COW year to December (as in D5); several overlapping GML spells (France in 258 switching sides in 1940) give the earliest start and the latest end, the latest end chosen at the coarser resolution (`date_latest_by()`, a fold of `date_later()`): two spells ending in the same latest month, one with a known day and one without, give that month at MONTH resolution (a tie at the coarser resolution keeps it; before 2026-10-26 the unknown day was sorted as day 1 and the day-dated spell was reported at day resolution; no such pair exists in the current `gml_part`, so no flag changed). Otherwise the dispute-level bounds apply (the dispute start month for an originator whose spell begins in the dispute's first year, else the year; the exact dispute end month when there is one, else the year). Two dates are compared at the coarser of their resolutions, so the tie conventions act at whatever resolution the pair of dates has. The pair onset is the later of the two participants' entries; when both were in the dispute before they were opposed (a side switch, 23 pairs in 12 groups, all in dispute 258) the onset is ambiguous across a year boundary and the COW onset year is used at year resolution (`coal_onset_ambiguous`). Membership is COW's (`cow_mid_dirdisps`); the 109 disputes where COW and GML disagree on who took part (107 COW participants absent from `gml_part`, 80 GML participants absent from COW) are listed in `build_log.txt`; GML dates are used for the participants both sources have, COW membership decides who is in the dispute. Helpers `participant_spell_dates()`, `date_cmp()`, `date_later()`, `date_earliest_by()`, `context_flags()`, `coalition_context()` in `helpers_data.R`.

**Tie conventions.** `coal_incl` (inclusive, default): a state entering on the same date as the group onset counts as present; coalition when at least one state besides the initiator and one onset-defining target is present (entered at or before the onset and not certainly exited before it). `coal_strict`: only strictly earlier entrants count; an onset-defining target that itself entered strictly before the onset (the initiator joined an existing pair) is the pair and does not make a coalition. Under either convention a group with two or more onset-defining targets (the initiator faces several targets from the first moment, e.g. Yugoslavia against 37 NATO states in dispute 4343, Iraq against Kuwait and Saudi Arabia in 1990, North Korea against South Korea and the USA in 1950) is multilateral by the spec's definition; the strict flag counted only strictly earlier entrants before 2026-10-26 and labelled such groups bilateral (audit fix 19; the inclusive flag already had them). Note that onset-defining is read at the resolution of the group's dates, so at month or year resolution every target tying at the onset counts. Resolution matters more generally: 138 groups are compared at year resolution (no month or day for the dates that decide them), so every co-participant of that year is a tie there, present under the inclusive and absent under the strict convention; 67 of them are inclusive-coalition and strict-bilateral purely from that resolution (95 before audit fix 19, which turned 28 of them into strict coalitions through tying targets). Of the 124 groups fix 19 moved to strict-coalition, 63 have their onset-defining targets tying at day resolution and 61 only at month or year resolution. Both columns are in `events.rds` (NA on escalation rows), so either can be selected without a rebuild. Strict never exceeds inclusive (asserted). A key the collapse merged from a bilateral and a coalition dispute takes the OR (38 inclusive / 36 strict of the 88 collapsed keys; 23 strict before fix 19); these keys are the only way a D8 group can be split by the switch (asserted at assembly, counted in the fit log; their groups' weights no longer sum to one decision, as with `fighting_at_ref`).

Counts (rebuilt `data/` of 2026-10-26, after the collapse): mid 3417 events, coalition 1256 inclusive (36.8%) / 950 strict (27.8%; 556 before audit fix 19); fmid 1144, 607 (53.1%) / 548 (47.9%; was 404); war 464, 362 (78.0%) / 339 (73.1%; was 280). Groups: 2874, coalition 762 inclusive / 466 strict (was 342; 185 groups have two or more onset-defining targets, 124 of them strict-bilateral by the entry comparison alone); entry comparisons at day resolution in 1943 groups, month 601, year 138, mixed (day and month, or coarser, within one group) 192; the group onset itself is day-dated in 2104 groups, month 632, year 138. Germany → Poland 1939: group onset 1939-03-25 (day resolution), one state present besides Germany → bilateral under both conventions (at month resolution the UK and France, entering 1939-03-31, would make it a coalition under the inclusive convention and bilateral under the strict one). Lag-3 M1b dry runs, inclusive ties (events kept → usable E, weights; stage 1 unchanged in every cell: N1 = 14,597, sum(y1) 2086 mid / 695 fmid): mid `_bi` 2161 → E 2066, weights 1951.8, 546 orphan initiations; mid `_co` 1256 → E 1192, 742.9, 1408 orphans; mid `_co_drop3` drops disputes 258 (104 coalition events), 3957 (53), 4186 (38) → 1061 → E 1005, 670.1; fmid `_bi` 537 → E 499, 448.8; fmid `_co` 607 → E 556, 292.3; fmid `_co_drop3` drops 258 (104), 3957 (53), 51 (30) → 420 → E 392, 256.3; strict ties, fmid (after audit fix 19): `_bi_strict` 596 → E 544, weights 491.9, `_co_strict` 548 → E 511, 249.1 (before: 740 → 673 and 404 → 382). Groups split by collapsed keys: 4 in mid, 0 in fmid (inclusive ties).

**Switches and preset.** `--context=bilateral|coalition`, `--coal_ties=inclusive|strict`, `--coal_drop=top3` (section 4); cells `<cell>_bi`, `_co`, `_co_strict`, `_co_drop3`. Preset `context` (section 5): `sbatch --export=ALL,PRESET=context v2/slurm/04_robustness.sbatch` fits M1b lag 3 for mid and fmid under bilateral, coalition and coalition without the top-3 coalition disputes (default ties; no war). Stage-1 state-years whose events are all in the other context keep y1 = 1 without a stage-2 event (orphan initiations, allowed as in the main cells and counted in the fit log).

**Comparison.** `Rscript v2/R/06_context_compare.R --sample=mid --lag=3 [--coal_ties=strict] [--r0=0.5] [--min_decisions=3]` loads `fit_<cell>_bi.rds`, `fit_<cell>_co.rds` and, when present, `fit_<cell>_co_drop3.rds` (production fits of the current data, same stage 1 asserted) and writes `output/context_compare_<group>.csv` (long table), `_crosstab.csv`, `_states.csv` and `.md`, where `<group>` is the cell name without its context suffix, in `cell_name()` order (`fmid_lag3_all_pr_M1b_strict_noww2` for the fits `_bi_strict_noww2` / `_co_strict_noww2`). Over the initiating states with at least 3 weighted stage-2 decisions (sum of w_e) in both fits, per axis: the correlation of the posterior-mean `mu_state` across contexts (a correlation of posterior MEANS, attenuated by the estimation noise of both fits, so a value below 1 is not by itself a context effect; the per-draw correlation reported until 2026-10-26 was removed because with draws paired by index it is attenuated far more and excluded 1 under a simulated null where both contexts share one truth, 0.60 [0.48, 0.71] against a posterior-mean correlation of 1.00; audit fix 20), the mean shift coalition minus bilateral per draw (draws paired by index; the fits need the same chains × iterations) with its 5 / 95% interval, and the MAP-type agreement (cross-tab and share) at r0. The leverage block repeats this for coalition_drop3 vs coalition. The role block splits originator and joiner pairs (`is_joiner_pair`) within each context: `mu_state` is one a_i per state and is not split by role in the fitted model, so the script reports the raw weighted mean chosen-target gap (the scaled x of the chosen alternative) per context × role × axis and, within the coalition context, the per-state correlation and mean difference joiner minus originator over states with 3 weighted decisions in both roles; the output says these are data descriptives, not posterior quantities.

**Known limitation.** Stage 1 does not distinguish bilateral from coalition opportunities: the initiation equation and the inclusive value are the same in both context fits, so the context split is a stage-2 comparison only, and the orphan initiations above enter stage 1 with the full IV. Day-resolution dates serve the context flag only; the escalation and choice-set rules stay at month resolution (6.3).

## 11. Dual typology stage (b): the M1c model

PI-approved spec of 2026-10-27. Stage (a) (section 10) read coalition targeting off split-sample refits and found, on the lag-3 M1b fits, mostly a population shift (mid: Σ[1,2] bilateral 1.52 vs coalition 6.07, μ0 material −1.77 vs −2.97; fmid: Σ[1,2] −0.54 vs 4.58, μ0 material −0.91 vs −2.73) and, within coalitions, different aim for originators and joiners (raw mean chosen gaps, mid coalition: originators (+0.27, +0.65), joiners (−0.05, +0.24)). Stage (b) puts every event in ONE model with group-specific shifts: the model code **M1c**, its own Stan program `stan/m1_context.stan` (derived from the joint "b" variant of `m1_latent_additive.stan`; the two existing programs are untouched, so their source hashes still guard the running fits), compiled by `compile_models.R` with its own sidecar `stan/build/m1_context.sha256`.

**Groups.** Three stage-2 event groups from two existing columns of `events.rds` (`stage2_groups()` in `helpers_data.R`, computed at assembly for every model and returned as `ev$grp`; only the M1c fit passes them to Stan as `ev_grp`): the coalition flag `coal_incl` of the event's D8 group and the INITIATOR's COW originator flag `orig1` (1 = originator, 0 = the initiator entered the dispute after its onset; after the D1 direction rule `orig1` always describes the initiator; a key collapsed from several disputes takes the max, so an initiator that originated any of them is an originator). joiner = `orig1 == 0` whatever the coalition flag says (role decides); bilateral = `coal_incl == FALSE` and `orig1 == 1` (the reference group); coalition leader = `coal_incl == TRUE` and `orig1 == 1`. Every event is in exactly one group (asserted). **PI decision 2026-10-27 (item 6, initiator-role-only joiner).** The first stage-(b) version used the build's pair-level flag `is_joiner_pair` (TRUE when EITHER side has `orig = 0`), which put an originator initiator facing a joiner target into the joiner group; the joiner role is now the initiator's own. The two definitions differ exactly on the pairs with `orig1 = 1` and a joiner target: 277 of the 848 mid joiner-pair events and 168 of the 548 fmid ones (sample events), which move to the bilateral / leader groups according to `coal_incl`; a joiner initiator always makes a joiner pair, so the role-only joiner group is a subset of the pair-level one (asserted in the tests). The `pairs = originators | joiners` switch is a separate, unchanged feature: it filters the STAGE-2 events by the pair-level `is_joiner_pair` (and recomputes y1), so `pairs = joiners` keeps every event with a joiner on either side, while the M1c joiner group holds only the events whose initiator joined. The groups always use `coal_incl` (the stage-(a) tie convention `coal_ties` applies to the context filter only). Lag-3 counts under the role-only definition (sample events before the choice-set join → usable events, D8 weight sums, initiating states): mid 3417: bilateral 2160 (2043.2) → 2065 (1950.8, 144 states), leader 686 (426.4) → 636 (401.9, 86), joiner 571 (347.9) → 557 (342.0, 104); fmid 1144: bilateral 537 (486.0) → 499 (448.8, 89), leader 227 (127.0) → 188 (107.6, 37), joiner 380 (189.6) → 368 (184.7, 75). (Pair-level definition, for the record: mid usable 1961 / 490 / 807, fmid 457 / 88 / 510.) The fit log and `obj$group_table` carry these per cell, with the pair-level joiner-pair count beside them.

**Model.** Stage 2 of event e by state-year n in group g:

```
U_g,ij = −½ (x_ij − μ_e)' Σ_g⁻¹ (x_ij − μ_e) + b_j + z_ij'γ
μ_e    = μ0 + δ_lead·[g = leader] + δ_join·[g = joiner] + X_n β + a_i        (δ_lead, δ_join are 2-vectors: material, relational)
Σ_g    = diag(σ_g) R diag(σ_g),   R = [[1, ρ], [ρ, 1]]  shared across the three groups (PI decision), σ_g a positive 2-vector per group
IV_n   = log Σ_{j ∈ C_n^{iv}} exp U_bilateral,ij                                  (the reference group's utility; see below)
```

**`--variant=mid3` is refused (audit P1-1, PI decision 2026-11-10).** The lag-3 MID-history choice set was built as specified on 2026-11-08 and then dropped from the grid. A conditional logit needs the chosen target in its set, so every event was scored against the history rows of its state-year plus its own chosen target. When the chosen target has no MID history in t − 3..t − 1 it is the ONLY non-history member of its set. No other choice could have produced that set, so the term P(j | H ∪ {j}) is not a valid conditional probability and the estimator is inconsistent for those events. They are 420 of the 705 usable fatal pairs events (60%) and 160 of the 300 jointly fatal ones (53%). The distortion is mechanical in `dy_mid_tm1`, which is half of the history rule. Widening the window to include year t would give every chosen target history, and would then define the set by the outcome. `parse_spec()` and `cell_name()` stop on the value with this reason (`MID3_REFUSAL` in `spec.R`). ## 14. Run 1, the opportunity-weight sensitivity (built 2026-11-10)

A sensitivity specification on the run-7 cell (M1c, bcj roles, directed Z, lag 3, full choice set). It is NOT a consideration-set model. The quantity q_ij is called an **opportunity weight** throughout and never a consideration probability (design synthesis of 2026-11-08, S1 and S2). Every switch defaults to the existing behaviour, `m1_context.stan` is untouched, and with the switches off every cell name, spec string and Stan data list is unchanged (`test_opp_weights.R`, and the existing pins).

### 14.1 What the weights are

An auxiliary logit of militarized contact, fitted outside the Stan program (`R/08_opportunity_weights.R`, functions in `R/opp_weights.R`).

| element | choice |
|---|---|
| rows | every directed dyad-year (i, j, t) of the cell foundation's `alts_lag3_all.rds`. The model is fitted on the January stage-1 IV rows (`in_iv = 1`, already-fighting at January removed, the rows the IV sums over) and predicts every row, the 284 (pairs) / 318 (dymid) stage-2-only rows included, since stage 2 needs their offset |
| outcome | a directly interacting Dyadic MID onset between i and j in year t, undirected, from `v2/data_dymid/events.rds` under BOTH foundations (every row of that file, escalation rows included). `--opp_outcome=host3` is the second version, onsets whose dyadic hostility max(`hostlev1`, `hostlev2`) is 3 or more |

| fit | logit MLE, expanding window. Year t is predicted from a fit on the years before t. **The five draws.** Five standard-normal vectors z_d are drawn once (seed 123). In every window the d-th coefficient vector is b̂ + L z_d with L the Cholesky factor of that window's covariance **clustered on the undirected dyad** (`oppw_vcov_cluster()`, the CR1 sandwich, equal to `sandwich::vcovCL(type = "HC1")` on a toy fit; the two directed copies of a dyad-year and all years of a dyad are one cluster, 20,570 clusters in the last window). The model-based covariance used before the audit was too small. In the last window the clustered SEs are 2.2 to 3.1 times the model-based ones on the structural coefficients (1.3 on A4, 1.4 on the intercept). A draw is a draw of the FULL coefficient vector of every window, with common random numbers across windows, and gives one coherent ln q column for all rows. Nothing is drawn per row.

### 14.2 The offset and why it is a sensitivity

Stage 2 becomes U_ij = spatial + b_j + Z_ij'γ + λ ln q̂_ij with Z the directed Z unchanged (`tgt_major` and its product stay in Z). The stage-1 IV carries the same term inside its log-sum, IV = log Σ q̂^λ exp(V) over the IV rows of the reference-group utility, the convention of `m1_context.stan`. The offset is a data vector (`opp_off` = λ ln q̂, formed in `02_fit_model.R`) of the copy `stan/m1_context_offset.stan`, which adds it where Z γ is formed. No parameter is added and ln q̂ is not centred.

| `--opp_weight` | suffix | what it is |
|---|---|---|
| `0` | `_opw0` | the current model. The Stan data are those of the cell without the switch plus a zero vector, and the log density, gradient and generated quantities are identical to `m1_context.stan` to the last bit (tested) |
| `0.5` | `_opw05` | half the offset |
| `1` | `_opw1` | the full offset. `--opp_draw=1..5` (`_d1` to `_d5`) conditions on one auxiliary draw instead of the MLE |

Reading. P(fatal_ij) = P(MID contact_ij) × P(fatal | contact_ij). The auxiliary outcome is itself a realisation of targeting, so the offset subtracts part of the target preference along with opportunity. At λ = 1 the spatial parameters μ, Σ and ρ describe **escalation given contact propensity**, not target selection over the full opportunity structure. A smaller ρ at λ = 1 is "residual jointness given MID propensity", not "debiased jointness". The paper's estimand stays target selection (λ = 0), and λ ∈ {0.5, 1} is reported as "robust to conditioning on militarized contact propensity". The λ values are fixed settings, not estimates.

Uncertainty of q̂. At λ = 1 the five draw-conditional fits are combined by `R/09_opp_combine.R` into the equally weighted mixture of the conditional posteriors (same number of posterior draws per fit, stacked). The table `oppw_mixture_<cell>.csv` reports, for μ (`mu0_g`), σ (`sigma_g`) and ρ (`rho_x`), the point fit's SD, the mixture SD, the SD of the conditional means across the draws and whether mixture SD / point SD exceeds 1.10.

Diagnostics per cell (`oppw_cell_<cell>.csv`, the log, and `obj$opp` of the saved Stan data and fit). PRIMARY, the within-set rank of each chosen target, the share of the event's own stage-2 set with a smaller q̂. Reported by role as the median rank and the chosen targets in the bottom 5% and the bottom 25% of their own set, in event counts and in composite (D8) weights. Secondary, the chosen targets below the 5th percentile of q̂ pooled over all alternative rows of the cell. That pooled measure is era-confounded (q̂ falls with system size, so nearly every row under the threshold is after 1990 and no early event can be flagged) and is kept for continuity only. Also the medians by role, and for the non-initiating state-years, of Σq and N_eff = (Σq)² / Σq² over the state-year's IV rows.

**Two limits of the stage-1 side (documented, no code).** (a) Year-level noise. The decade rule gives a year the effect of the latest decade with three training years and an onset, so war decades are carried forward (1946–49 were predicted at about 3.6 times the observed onsets under the first build) and the observed / predicted ratio by year is noisy. A year-level shift of ln q̂ cancels in the stage-2 softmax and does not cancel in the IV, and stage 1 has no year effects. (b) τ is not comparable across λ. At λ = 0 the IV varies almost only between years. At λ = 1 it is a MID-propensity mass that carries the history and A4 terms, correlates with `ongoing_tm1`, `log_prior_mids` and `multi_mid_jan`, and now with the initiator's level through `M_lvl_i`. τ at λ = 1 reads "initiation rises with MID-propensity mass", and α on those W columns shifts with it. Compare μ, Σ and ρ across λ, not τ or α.
