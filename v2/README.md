# Strategic targeting — v2 pipeline (R + Stan)

Two-stage spatial choice model of MID initiation and target selection, estimated jointly in Stan.
Built fresh on branch `v2-rebuild`; the old code is reference only. Simulation-tested; no real-data model has been run yet.

## Model (implemented exactly as decided)

Stage 1 (state-year n, state i): `y1 ~ Bernoulli(logit⁻¹(α0 + W'α + c_i + τ·IV))`.
Stage 2 (event e by state-year n, choice set C_n of all other system members at t with positions at t−1):

```
U_ij = −½ (x_ij − μ_n)' Σ⁻¹ (x_ij − μ_n) + b_j + z_ij'γ [+ u_i'v_j in M2]
x_ij = (M_i − M_j, R_i − R_j) at t−1          μ_n = μ0 + X_n β + a_i   (μ0 is 1 × D, β is P × D)
P(j | n) = softmax over C_n^{s2}               IV_n = log Σ_{j∈C_n^{iv}} exp U_ij
(c_i, a_i1, a_i2) ~ MVN(0, Ω)                  b_j ~ N(0, σ_b) (soft sum-to-zero)
```

Two choice sets per state-year (Codex review P1-1, PI choice "A′", 2026-10-24). C_n^{iv}, the stage-1 IV set, excludes the states already fighting i at January of t, by the same rule for every state-year, so IV_n cannot depend on whether (i, t) initiated. C_n^{s2}, the stage-2 set, excludes the states already fighting i at the state-year's reference date (the start of its earliest non-escalation event). The two coincide for every non-initiating state-year. The data hold one row block per state-year, the union of both sets, with 0/1 flags `in_iv` and `in_s2`; the Stan programs sum IV over the `in_iv` rows and run the softmax over the `in_s2` rows (see "Data decisions").

μ0 is the intercept of the ideal target position (added 2026-10-23, PI-approved). a_i is mean zero and X has no intercept column, so without μ0 the population-average preferred gap was fixed at 0, a "peer" world by construction. Because x is the initiator-minus-target gap, μ0 is the average preferred gap itself, the paper's central quantity (bully > 0, peer ≈ 0, challenger < 0). It is a `row_vector[D]` (length 1 in the m / r models) with prior μ0 ~ N(0, `prior_mu0_sd`), `prior_mu0_sd` = 2 set in `build_stan_data()`. Since 2026-10-24 the main X holds only the two power changes, so μ0 is the ideal gap of a state with zero power change (every W control is centred, so α0 is the stage-1 log-odds at zero power change and average controls); under `--full_controls` X carries the centred monadic controls as well and μ0 is the ideal gap at their averages. `mu_state` at `x_ref` = μ0 + x_ref'β + a_i.

Families: `m1_latent_additive.stan` (M1) and `m2_ame.stan` (M2 = M1 + u_i'v_j, K latent dimensions, K is data). Eight model codes, two data flags.

| code | `D_mode` | `joint` | stage-2 targeting space |
|---|---|---|---|
| M1m / M2m | 1 | – | material only (x = dM, scalar μ, scalar Σ, Ω 2×2 over (c, a)) |
| M1r / M2r | 2 | – | relational only (x = dR) |
| M1a / M2a | 3 | 0 | both dimensions, independent (Σ diagonal, corr(a_1, a_2) = 0; corr(c, a_d) free) |
| M1b / M2b | 3 | 1 | both dimensions, joint (full Σ, full Ω) |

Stage 1 is identical in all eight (same W, which includes dM_i and dR_i); only the stage-2 utility and hence the IV differ. All eight score the same events and choice sets, so LOO compares like with like. The correlations shared across models carry the same prior ((r+1)/2 ~ Beta(2.5, 2.5), the LKJ(2) marginal for a 3×3 matrix), so m / r / a / b differ only by their restrictions. Generated quantities: `log_lik_stage1[N1]`, `log_lik_stage2[E]`, `mu_state[S,2]` (at `x_ref`), `mu_event[E,2]`, `Sigma`, `Omega`, `R_Om`. Choice sets are ragged (`cs_start`/`cs_end`) with the per-row flags `in_iv` / `in_s2` (a block whose rows are all in both sets takes the pre-review code path, so the log density is identical there), and an optional sampled-alternatives mode (`sampled = 1`, IV corrected by log(n_full/n_sub), where n_full is the IV-set size; the IV rows are drawn from the IV set and the event blocks from the stage-2 set, so every sampled row carries `in_iv = in_s2 = 1` and the programs reject anything else).

## Data decisions (flags at the top of `01_build_data.R`)

* Events (PI decision 2026-10-24, joiners in the main specification). An event is a Side A participant → Side B participant pair of a COW-MID dispute, joiners included, with onset year equal to the first year that pair appears in the dispute, one direction per dispute pair, and every A × B pair of a multilateral dispute is an event. `INCLUDE_JOINERS = TRUE` is the main build (FALSE reproduces the originator-only base of 2770 events). With joiners there are 3720 events, of which 950 are joiner pairs (`is_joiner_pair`, TRUE when either side has `orig = 0`; kept for tabulation, never a covariate). The war sample grows most, from 127 originator pairs to 552 pairs, because the two world wars contribute most of their pairs through joiners. The fatal-MID rules of 2026-10-23 apply unchanged to joiner pairs (with the pair-level war coding of 2026-10-24 the joiner pairs are coded cow 897, mic_fill 50, uncoded 3; the war rule no longer adds any).
* Ongoing disputes (PI decision 2026-10-24, month resolution since the second decision of that day). Stage 2 is target selection, so a new dispute against a state the initiator is already fighting is escalation, not selection. An event is an escalation when i and j are both participants in a different dispute that started before the event's dispute start date and had not ended by it, compared at month resolution. The year-level version of this rule (pair in a dispute active in year t with onset before t) mislabelled about 45% of the escalations (China → USA 1950, the Korean War, was dropped because a short 1949 incident had a 1950 row) and missed re-entries within a year. Dates come from `cow_mid_disps` and are dispute-level, because peacesciencer 1.2.0 ships the dispute start month and year (`stmon`, `styear`) and the duration in days (`mindur`, `maxdur`) but no end month and no participant-level dates (`cow_mid_dirdisps` has years only). The end date is therefore a bound, not a point, between the first day of the start month plus `mindur` and the last day of the start month plus `maxdur`, clamped to the dispute's last year in the directed dispute-years (198 of 2436 disputes have an exact end month, 1954 a two-month span, 284 wider, 10 inconsistent with the duration and given the whole last year). A pair that enters a dispute after its first year has an unknown entry month (the whole year), a pair that leaves before the dispute's last year an unknown exit month, and a pair that leaves and re-enters has separate spells. Every comparison is three-valued. When it is undecided the year rule decides and the fallback is counted. Across the 43,874 (event, other dispute) comparisons 176 are undecided (80 because the event's own pair entered its dispute after the dispute's start year, 35 because the other dispute's pair entered late, 61 because the end bound straddles the event month); 143 of 3720 events have a decision that rests on a fallback. Result 217 escalations under the month rule against 288 under the year rule (106 no longer escalations, 35 new ones; 60 joiner pairs, 157 originator pairs). Escalations stay in `events.rds` with `escalation = TRUE` (`escalation_year` keeps the year rule, `esc_fallback` marks fallback decisions, `ev_start_lo` / `ev_start_hi` the event's date interval as a month index) and are excluded from every sample flag, so they are in neither stage 2 nor y1. For choice sets each state-year (i, t) has TWO sets since the Codex review of 2026-10-24 (P1-1, PI choice "A′"). The stage-1 IV set drops alternative j when i and j are in a dispute active at January of t that started before it, for every state-year alike, so the stage-1 regressor IV_n uses no information about the state-year's own events (the previous rule used the event date for initiators and January for non-initiators, which made the IV set a function of y1). The stage-2 set drops j when i and j are in a different dispute active at the state-year's reference date, the start of its earliest non-escalation event when it initiates and January of t otherwise, that started before it (unchanged). Both rules are the month rule with the year fallback, and nothing after the respective date enters. For a non-initiating state-year the two sets are identical. The alternatives files keep one row block per state-year, the union of both sets, with the flags `in_iv` and `in_s2` (`choice_set_flags()` in `00_helpers.R`); rows in neither set are removed. At h = 3 the IV rule drops 3724 of 1.72 million rows and the stage-2 rule 3582; 3501 rows are in neither set and leave the file, 1,720,058 remain, of which 81 are IV only and 223 stage 2 only; 229 of the 2096 initiating state-years have different sets (before the P1-2 joiner fix below these were 249 of 2165 initiating state-years, 130 IV-only and 226 stage-2-only keys, as the review reported). Escalation flags are event-date based and unchanged. Because the stage-2 set is fixed at the reference date, a later event of the same state-year whose pair was still fighting at that date (their dispute ended between the reference date and the event) has no stage-2 row (it may keep an IV-only row with `in_s2 = 0`). There are 31 such events (29 after the duplicate collapse; 7 in fmid, 1 in war), flagged `fighting_at_ref`. They keep every sample flag, so y1 is unchanged, and leave stage 2 only, like events whose target lacks positions; the build lists them and stops if any other non-escalation event loses its stage-2 row. This is a deviation from the requirement that every non-escalation event's chosen alternative be in its choice set, which cannot hold with one stage-2 set per state-year, and is flagged for the PI. The build logs the escalation and alternative counts under both rules with examples, asserts that the IV flag equals the January rule on every retained row and that only initiating state-years have differing sets, and stops if any state-year with rows has an empty IV set or any initiating state-year a stage-2 set that is empty or holds only its chosen target (`assemble_cell()`, `build_stan_data()` and the Stan programs repeat these checks). Helpers `dispute_date_bounds()`, `pair_dispute_intervals()`, `month_rule()`, `flag_escalations_month()`, `reference_dates()`, `already_fighting_keys_month()` (reference `NULL` = January for every state-year) are in `00_helpers.R` and unit-tested on toy disputes (ended before the new start in the same year, still active, undecided month, and a regression fixture in which adding or moving a state-year's events changes its stage-2 set but never its IV set). Exact participant-level dates would need the COW MIDB 5.0 file, which is not in the repository.
* Joiner entry month (Codex review P1-2, 2026-10-24). A pair with a joiner on either side (`orig == 0`) whose spell begins in the dispute's first year used to receive the dispute's exact start month although the joiner's entry month is unknown. Its entry interval is now [dispute start month, December of that year] with `start_exact = FALSE`; originator pairs keep the exact start, later entrants keep the whole entry year. Undecided comparisons fall back to the year rule as before. On the COW data 1154 of 7456 directed spells (577 undirected pairs) are affected; escalations fall from 217 to 199 (18 no longer escalations, 0 new), and the events whose decision rests on a fallback rise from 143 to 219. The build rebuilds the pre-review intervals only to log these before / after counts.
* Same-year duplicates (PI decision 2026-10-24). After the escalation exclusion, events with the same (initiator, target, year) from different disputes collapse into one event (`collapse_duplicate_events()`). Sample flags and fatality codings are ORed, `dispnum` keeps the smallest dispute number, `dispnums` lists them all, `n_disputes` counts them, `is_joiner_pair` is FALSE when any collapsed row was an originator pair, and escalation rows are untouched. With the review fixes 188 rows in 93 keys collapse into 93 events (mid 3521 → 3426, fmid 1167 → 1153, fmidcow 990 → 983, fmidub 1189 → 1172, war 478 → 469), so the likelihood sees one chosen alternative per (i, j, t), asserted in the build and in `assemble_cell()`. The no-WWII sample flags `in_<sample>_noww2` (Codex review P2-3) are the sample flags of the non-WWII source rows alone, ORed in the same collapse, so a key that mixes a WWII and a non-WWII dispute stays in the `--drop_ww2` sample only when a non-WWII dispute qualifies, and its fatal / war coding there comes from the non-WWII disputes only. One collapsed key mixes the two (UK → Bulgaria 1941, disputes 258 and 3871): it stays in the no-WWII `mid` sample and leaves the no-WWII `fmid` and `war` samples; the other five collapsed WWII keys are WWII-only and leave all of them.
* WWII (appendix option `--drop_ww2`, cell suffix `_noww2`, not in the main grid). `is_ww2` marks the events of 16 COW-MID disputes, 258 (the Second World War itself) plus every war-level dispute that starts between 1939-09 and 1945-09, whose highest action is 21 (join interstate war) and whose dyad appears in COW inter-state war 139 in `cow_war_inter` (235, 339, 414, 418, 518, 2725, 3701, 3705, 3717, 3724, 3813, 3820, 3822, 3826, 3827, the run-ups to a state's entry into the war). Disputes 157, 179, 183 and 613 are wars of their own (COW wars 130, 142, 136, 145) and stay. The rule is `ww2_disputes()` in `00_helpers.R`, the list is asserted against `WW2_DISPNUMS`, and the build log prints every candidate with its reason. 134 of the war events are WWII; `--drop_ww2` removes them from stage 2 and their initiations from stage 1 using the `in_<sample>_noww2` flags (above), so a state-year whose only events were WWII gets y1 = 0.
* Samples: `mid` (all), `fmid` (fatal, main coding), `fmidcow` (fatal, COW-only coding; appendix), `fmidub` (fatal, upper bound; appendix), `war` (pair-level war, at least one participant at hostility level 5).
  * War is coded at the pair level (PI decision 2026-10-24, revised the same day). An event is a war event only when the dispute is war-level (hostility level 5) and at least one participant of the pair reached hostility level 5 itself (participant `hostlev1` / `hostlev2` in `cow_mid_dirdisps`, maximum over the pair's years). The dispute-level coding is kept as `war_disp`. Of the 552 dispute-level war pairs 508 are war pairs (44 had neither participant at level 5, mostly peripheral Gulf War and Iraq 2003 coalition members); after the escalation exclusion the war sample has 476 events instead of 520, and after the duplicate collapse 467, with a WWII share of about 28%. A first version required both participants at level 5 (329 events); the PI chose the less strict rule. The war rule in the fatal coding uses the pair-level definition and adds 29 events.
  * COW fatality: an event is fatal if either side's fatality ≥ 1 or the dispute fatality ≥ 1; negative codes → missing. 229 of 2,770 events have every COW fatality code missing.
  * `fmid` (PI decision 2026-10-23) applies four rules in order. (a) Wars are fatal by definition, since COW wars require 1,000+ battle deaths. With the dispute-level war coding this added 20 events, 14 with missing COW fatality and 6 that COW codes as non-fatal (MIC codes 5 of the 20 as non-fatal and omits 11; the war rule takes precedence); with the pair-level coding of 2026-10-24 it adds none. (b) A coded COW fatality value is kept as is. (c) When every COW code is missing, the event takes the MIC 1.0 value (Gibler et al., Militarized Interstate Confrontations; confrontation-level `fatalmin` ≥ 1; MIC `micnum` = COW `dispnum`). MIC fills 182 events (112 fatal, 70 non-fatal). (d) When COW and MIC are both missing, the event takes the GML MID 2.2.1 coding of the same directed pair (Gibler, Miller and Little 2016; peacesciencer `gml_mid_ddydisps`; same rule as COW). GML codes 11 of the remaining 33 events (5 fatal, 6 non-fatal). 22 events are coded by no source and stay non-fatal. Result 632 fatal events (495 under COW only). `fatal_source` in `events.rds` records which rule set each event.
  * No source overrides an earlier coded value (COW, then MIC, then GML). Where both code fatality they disagree on 120 events, which the build logs but does not use. MIC also omits 700 of the 2,770 COW events and recodes Side A for some disputes; the event base and sides stay COW.
  * `fmidcow` is the earlier rule (missing → not fatal, no war rule) and reproduces the pre-2026-10-23 `fmid` exactly.
  * `fmidub` is the bounds check. It equals `fmid` plus the 22 events no source codes, counted as fatal (654 events). If `fmid` and `fmidub` results agree, the uncoded events do not drive the fatal-MID findings.
  * MIC source file `data_raw/mic-conf-1.0.csv` is checked against a sha256 in `00_helpers.R` (`MIC_CONF_SHA256`); see `data_raw/SOURCE.md`.
* Positions (PI decision 2026-10-23, replacing the within-year standardisation of 2026-10-22). M = log CINC share and R = log IGO PageRank, both left in raw log units. CINC share and PageRank each sum to one over the system in a year, so M is the log share of world capabilities and R the log share of network centrality. The stage-2 gaps x_ij = (M_i − M_j, R_i − R_j) are therefore log ratios between the two states. The two axes have very different spreads (SD about 3.27 log points for M and 0.52 for R), so each gap is divided by one constant per axis, the same for every year, lag and choice-set variant (PI decision 2026-10-23, option 1). The constant is the SD of the within-year gap over all ordered pairs of distinct states (`gap_scale()` in `00_helpers.R`), 3.268 for M and 0.524 for R, stored in `change_scale.csv` with h = NA and the raw log ratios kept as `dM_logratio` and `dR_pr_logratio`. One model unit on the material axis is therefore a 26-fold ratio of CINC shares, and on the relational axis a 1.7-fold ratio of PageRank. No script converts estimates back. To read a μ, Σ or r0 value in log ratios, multiply it by the constant for its axis in `change_scale.csv` (rows with h = NA) by hand; `03_extract.R` and `typology.R` report in the scaled units. The build stops and lists any state-year with a zero or missing CINC share, and likewise any non-finite or non-positive PageRank, instead of flooring it (none exist; smallest share 2.4e-7, smallest PageRank 7.8e-4). PageRank weights are shared IGO memberships with isolates included as vertices. The eigenvector centrality `R_eig` is unchanged (still standardised within year); it is not used in the main grid and the eigenvector robustness run is unscheduled. Years with all-missing IGO data are dropped and listed in `build_log.txt` (`IGO_FILL = "drop"`; `"locf"` carries the latest IGO year forward). With peacesciencer 1.2.0 no year is all-missing (1990 is partially missing and its NA dyads are treated as no shared membership). Why the change. On within-year z-scores a state's change over [t−1−h, t−1] moved with the growth of the system (correlation with the 3-year log growth in the number of states about +0.29 for M and +0.17 for R at h = 3), and the changes had SD 0.11 and 0.25, so the per-unit priors on β and α dominated the data.
* Changes (same decision). One state-level table per lag, `changes_lag{h}.rds`, built by `build_change_table()` in `00_helpers.R`. For every state in the system at t with positions at t−1 and t−1−h, the raw change is d = level(t−1) − level(t−1−h) in log units (calendar joins, kept as `dM_raw_h`, `dRpr_raw_h`). The transformed change `dM_h`, `dRpr_h` subtracts the mean raw change of all states that have a change in that year and divides by one pooled constant per lag and variable, the SD of the year-centred change over all rows of that lag. A value of zero means the state changed like the average state over the same window, and the units are pooled SDs (1 unit = 0.19 log points for M and 0.15 for R at h = 3; the constants are in `data/change_scale.csv`, in the manifest notes and in the build log). The same table supplies the initiator's change in stage 1 (dM_i, dR_i in W and X) and the target's change in stage 2. The build asserts finiteness, within-year mean 0, pooled SD 1, and |cor| < 0.02 between the transformed change and the 3-year log growth in the number of system states (the correlation is 0 by construction because the growth variable is constant within a year), and logs the raw and transformed correlations.
* Target changes in stage 2 (same decision). The alternatives files carry the target's transformed change `dM_j_h`, `dRpr_j_h` joined from the same table, and `z_columns()` includes both in Z for every model, the 1-D ones included. A target with no change value (no position at t−1−h, typically a recent entrant) gets 0 and `dch_j_missing = 1`; at h = 1, 3, 5, 10 this affects 21k, 62k, 99k and 185k of about 1.6–1.8 million alternative rows (220, 652, 1069 and 2063 target state-years). `assemble_cell()` adds `dch_j_missing` to Z only when it is non-constant in the assembled cell and logs that decision; `dM_j_h` and `dRpr_j_h` are centred over the assembled alternative rows like the other continuous Z columns, and the indicator stays 0/1 like the other dyadic indicators.
* Timing: positions at t−1; changes over [t−1−h, t−1]; dyadic controls (contiguity, ATOP defense/offense alliance, joint democracy polity2 ≥ 6, major-power count) at t−1; all via calendar joins.
* Conflict history: monadic and dyadic MID onset counts in the 10 years before the window starts, dyadic and monadic peace years as of window start, counted over every participant including joiners (consistent with the events; `INCLUDE_JOINERS` governs both). The main spec includes the two counts (`--conflict_history=TRUE` in `02_fit_model.R`), which enter as `log1p()` and are centred. The dyadic peace years left the main Z on 2026-10-24 and the monadic peace years left the main W later that day (see W / X / Z below); `--full_controls` restores the monadic ones.
* Lagged involvement at t−1 (PI decision 2026-10-24), always from every participant including joiners. `ongoing_tm1` (stage 1) is 1 when the state was in any MID active in year t−1 (mean 0.31 at h = 3). `dy_mid_tm1` (stage 2) is 1 when i and j were both in a MID active in t−1. After the already-fighting cut a remaining alternative can have `dy_mid_tm1 = 1` only when every dispute of the pair active in t−1 had ended by t, or when the row is a chosen event of a new dispute. At h = 3 it is 1 on 5938 of 1.72 million alternative rows and on 790 of 3300 usable mid events (56 of 487 war events). `assemble_cell()` stops if it is constant in a cell.
* Democracy and alliance NA → 0 with `*_missing` indicator columns kept in the data (not in the default spec).
* Choice sets: `all` = every other system member at t with positions at t−1, minus the already-fighting alternatives; `polrel` = the same restricted to contiguous (conttype 1–5) or either state a COW major power. Events whose target is outside the choice set are dropped from stage 2 (logged; the initiator's y1 stays 1).
* Control sets (PI decision 2026-10-24, minimal controls). Major-power status and alliance are components of material and relational power, so they are bad controls and left the main specification, and the main sets are as small as the design allows. Main W (stage 1) = initiator power changes dM_i, dR_i, `ongoing_tm1`, log1p monadic prior MIDs, democracy `dem_tm1` (P1 = 5). Main X (the μ shifters) = dM_i, dR_i only, no monadic controls (P = 2). Main Z (dyadic) = land contiguity, joint democracy, log1p dyadic prior MIDs, `dy_mid_tm1`, the target power changes dM_j_h and dRpr_j_h, plus `dch_j_missing` when it is non-constant in the cell (Pz = 6 or 7). `--full_controls=TRUE` (cell suffix `_fullctrl`) reproduces exactly the base specification of commit 8bf0ce1 (Codex review P2-4; `git show 8bf0ce1:v2/R/assemble_cell.R`), same columns in the same order. W = X = `dM_i`, `dR_i`, `cowmaj_tm1`, `dem_tm1`, `log_prior_mids`, `log_peace_years` (P1 = P = 6; the last two follow `--conflict_history`). ## Identification and estimation decisions

* Only Σ⁻¹ and Σ⁻¹μ are identified by the choice data (the −½ μ'Σ⁻¹μ term is constant across alternatives), so μ is recovered as Σ(Σ⁻¹μ); this is automatic in the parameterisation.
* The "a" model fixes corr(a_i1, a_i2) = 0 but keeps corr(c, a1) and corr(c, a2), parameterised so Ω is always PD (r2 = q·√(1−r1²)).
* AME: V column-centred (a column constant cancels in the softmax); the anchor block of U (K states with most initiations) is lower-triangular with positive diagonal; U/V scale is fixed by N(0,1) priors only. Procrustes alignment across chains in `03_extract.R` is a safety net and its rotation deviation is logged.
* Priors: μ0 ~ N(0, 2) per element (`prior_mu0_sd` is data, 2 from `build_stan_data()`), β ~ N(0, 1) per element (`prior_beta_sd` is data), σ_x ~ lognormal(0, 1), sd of random effects ~ half-N(0, 1), LKJ(2) on correlations, γ, α ~ N(0, 1), τ ~ N(0, 1), α0 ~ N(0, 2.5). The μ0 and σ_x scales were chosen when x had SD about 1.4 per axis. After the gap scaling x has SD about 1 per axis, so these priors keep roughly their intended weight.
* Main specification = the full all-states choice set, `--variant=all --sampled_m=0` (the defaults of `02_fit_model.R`); `polrel` and `--sampled_m` remain options for robustness and pilots. Sampled alternatives (`--sampled_m=m`) are an option with two outcome-separated samples. (a) IV rows, for every state-year, m alternatives drawn uniformly without replacement, ignoring outcomes, with IV = log-sum-exp + log(n_full/m); this estimate of the log partition sum is downward biased by Jensen's inequality, equally for initiating and non-initiating rows, and the bias shrinks with m. (b) Event rows, each event gets its own set of its chosen target plus m uniform others, independently per event, so the conditional-logit score is unbiased (McFadden 1978). Unit tests in `tests/testthat/test_sampled_alternatives.R` reproduce the review cases.
* Seed 123 everywhere.

## Typology outputs

Main output (`typology_<cell>.csv`): the 5-bin classification of posterior μ_i at `x_ref` with radius `r0` (default 0.5 in scaled gap units, i.e. 0.5 × 3.268 log points, about a 5-fold CINC ratio, on the material axis and 0.5 × 0.524, about a 1.3-fold PageRank ratio, on the relational axis; peer = within r0 of the origin; bully (+,+), challenger (−,−), hybrids off-diagonal). For 1-D models the single axis gives weaker / peer / stronger (μ > r0 means the state targets others positioned below it on that axis).

Appendix outputs, written by `03_extract.R` as well. (a) `typology9_<cell>.csv`, a 9-cell classification with a peer band on each axis (`--band_M`, `--band_R`, default r0): bully, challenger, peer, material / relational opportunist, material / relational challenger, compensator A (M down, R up), compensator B (M up, R down), with posterior cell probabilities and the modal cell; D = 2 only. (b) `reach_<cell>.csv`, posterior mean and 90% interval of r_i = ||μ_i|| and of |μ_i1|, |μ_i2|. (c) `focus_sigma_<cell>.csv` and `focus_states_<cell>.csv`, descriptive only: the single pooled Σ (SDs, correlation) and each state's empirical dispersion of its chosen targets' positions around the posterior mean μ at the event (SD per axis, correlation, n_events; fewer than 5 events flagged unreliable). The model has one pooled Σ; a state-varying Σ_i would be a model change for the PI to decide on, not something these files estimate.

## Within-chain parallelism (reduce_sum)

Both programs evaluate the likelihood as `reduce_sum_static` over state-years (stage-1 term, IV log-sum-exp and the state-year's stage-2 events in one slice; `grainsize` is data, N1 for one slice = the exact serial sum). `02_fit_model.R --threads_per_chain=k` sets `rstan_options(threads_per_chain)` and `grainsize ≈ N1 / (4k)`; request `cpus-per-task = chains × k` (08_main_grid.sbatch and 04_pilot.sbatch default to 8 threads per chain, 32 and 8 cpus, 4 GB per cpu). rstan 2.32 compiles with `-DSTAN_THREADS` by default and `compile_models.R` asserts it. Generated quantities are serial, so `log_lik` is identical across thread counts; the log density and gradient agree to 1e-10 / 1e-8 (tests/testthat/test_reduce_sum.R). Profiling on the 40-state simulated cell puts ~99% of the gradient in the utility computation over alternative rows (`sim/results/profile_breakdown.csv`); on this 2-core container 2 threads gave 2.1–2.4× and 4 threads (oversubscribed) 2.7–2.9× (`sim/results/threads_timing.csv`); the Roar curve must come from the pilot. Stan `profile()` sections are in both programs for CmdStan users. Compiling M2 needs about 3 GB with `v2/env/Makevars` (no `-g`, aggressive GC) versus >5.7 GB with R's default flags; copy it to `~/.R/Makevars` where memory is tight.
