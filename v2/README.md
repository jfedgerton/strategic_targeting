# Strategic targeting — v2 pipeline (R + Stan)

Two-stage spatial choice model of MID initiation and target selection, estimated jointly in Stan.
Built fresh on branch `v2-rebuild`; the old code is reference only. Simulation-tested (the report predates the 2026-10-25 model changes); a 24-cell real-data run of dd48506 is on the cluster, the changes of 2026-10-25 are for the next run.

## Model (implemented exactly as decided)

Stage 1 (state-year n, state i): `y1 ~ Bernoulli(logit⁻¹(α0 + W'α + c_i + τ·IV))`.
Stage 2 (event e by state-year n, choice set C_n of all other system members at t with positions at t−1), entering the log density as a composite likelihood with the dispute-level weight w_e (see "Coalition expansion"):

```
U_ij = −½ (x_ij − μ_n)' Σ⁻¹ (x_ij − μ_n) + b_j + z_ij'γ [+ u_i'v_j in M2]
x_ij = (M_i − M_j, R_i − R_j) at t−1          μ_n = μ0 + X_n β + a_i   (μ0 is 1 × D, β is P × D)
P(j | n) = softmax over C_n^{s2}               IV_n = log Σ_{j∈C_n^{iv}} exp U_ij
log density = Σ_n log Bernoulli(y1_n) + Σ_e w_e log P(j_e | n_e) + priors        w_e = 1 / (targets of initiator i in the same dispute and year)
(c_i, a_i1, a_i2) ~ MVN(0, Ω)                  b_j ~ N(0, σ_b) (soft sum-to-zero)
```

Two choice sets per state-year (Codex review P1-1, PI choice "A′", 2026-10-24). C_n^{iv}, the stage-1 IV set, excludes the states already fighting i at January of t, by the same rule for every state-year, so IV_n cannot depend on whether (i, t) initiated. C_n^{s2}, the stage-2 set, excludes the states already fighting i at the state-year's reference date (the start of its earliest non-escalation event). The two coincide for every non-initiating state-year. The data hold one row block per state-year, the union of both sets, with 0/1 flags `in_iv` and `in_s2`; the Stan programs sum IV over the `in_iv` rows and run the softmax over the `in_s2` rows (see "Data decisions").

μ0 is the intercept of the ideal target position (added 2026-10-23, PI-approved). a_i is mean zero and X has no intercept column, so without μ0 the population-average preferred gap was fixed at 0, a "peer" world by construction. Because x is the initiator-minus-target gap, μ0 is the average preferred gap itself, the paper's central quantity (bully > 0, peer ≈ 0, challenger < 0). It is a `row_vector[D]` (length 1 in the m / r models) with prior μ0 ~ N(0, `prior_mu0_sd`), `prior_mu0_sd` = 2 set in `build_stan_data()`. Since 2026-10-24 the main X holds only the two power changes, so μ0 is the ideal gap of a state with zero power change (every W control is centred, so α0 is the stage-1 log-odds at zero power change and average controls); under `--full_controls` X carries the centred monadic controls as well and μ0 is the ideal gap at their averages. `mu_state` at `x_ref` = μ0 + x_ref'β + a_i.

Families: `m1_latent_additive.stan` (M1) and `m2_ame.stan` (M2 = M1 + u_i'v_j, K latent dimensions, K is data). Eight model codes, two data flags.

| code | `D_mode` | `joint` | stage-2 targeting space |
|---|---|---|---|
| M1m / M2m | 1 | – | material only (x = dM, scalar μ, scalar Σ, Ω 2×2 over (c, a)) |
| M1r / M2r | 2 | – | relational only (x = dR) |
| M1a / M2a | 3 | 0 | both dimensions, independent (Σ diagonal, corr(a_1, a_2) = 0; corr(c, a_d) free) |
| M1b / M2b | 3 | 1 | both dimensions, joint (full Σ, full Ω) |

Stage 1 is identical in all eight (same W, which includes dM_i and dR_i); only the stage-2 utility and hence the IV differ. All eight score the same events and choice sets, so LOO compares like with like. The correlations shared across models carry the same prior ((r+1)/2 ~ Beta(2.5, 2.5), the LKJ(2) marginal for a 3×3 matrix), so m / r / a / b differ only by their restrictions. In the a models that prior is the LKJ(2) density restricted to corr(a_1, a_2) = 0, p(r_1, r_2) ∝ 1 − r_1² − r_2² on the unit disk, whose marginals are exactly Beta(2.5, 2.5) (review fix 2026-10-25, B4; the previous code put two Beta marginals on the disk, which gave Var ≈ 0.158 instead of 1/6); Σ's correlation ρ in the b models carries the same explicit marginal (it was the implicit uniform of the bounds). Both are verified by prior-only runs in `tests/testthat/test_priors_a_vs_b.R`. Generated quantities: `log_lik_stage1[N1]`, `log_lik_stage2[E]`, `mu_state[S,2]` (at `x_ref`), `mu_event[E,2]`, `Sigma`, `Omega`, `R_Om`. Choice sets are ragged (`cs_start`/`cs_end`) with the per-row flags `in_iv` / `in_s2` (a block whose rows are all in both sets takes the pre-review code path, so the log density is identical there), and an optional sampled-alternatives mode (`sampled = 1`, IV corrected by log(n_full/n_sub), where n_full is the IV-set size; the IV rows are drawn from the IV set and the event blocks from the stage-2 set, so every sampled row carries `in_iv = in_s2 = 1` and the programs reject anything else).

## Data decisions (flags at the top of `01_build_data.R`)

* Initiator direction (PI decision 2026-10-25, D1; `DIRECTION` at the top of `01_build_data.R`, set by the environment variable `V2_DIRECTION`). COW-MID Side A is the side that took the FIRST codable action, not the aggressor. In dispute 258 (the Second World War) Side A is Poland and the Allies, so the Side A rule produced Poland → Germany, UK → Germany and USA → Germany in 1939–41 and never Germany → Poland. For wars the standard aggressor coding is COW's war initiator, so for disputes at hostility level 5 that can be linked to a COW inter-state war (`cow_war_inter`, which has the war sides `sidea1 / sidea2` and the state-level initiator flags; every COW war has exactly one initiating side, asserted) the direction follows COW's war-initiating side. The rule has two steps. (a) Pair level. A MID pair (i, j) with onset year t is matched to the COW war dyad-years (i, j) in t or t + 1 (`WAR_DIR_WINDOW = 1`; MID onsets precede war onsets, the crisis year is often the year before the fighting reached war level). Every matched row votes: reverse when j's war side initiated, keep when i's did; unanimous votes decide the pair (`dir_source = "cow_war_pair"`, whether reversed or confirmed), mixed votes (two wars with opposite initiators) leave Side A. On the data 363 of the 552 war-level pair events match (310 at t, 53 at t + 1 only; t + 2 would add 5, any later ongoing year 29, not used); 160 are reversed, 201 confirmed, 2 ambiguous (dispute 611 / 1360, Vietnam–Cambodia, matched to wars 163 and 176). (b) Dispute level. The unmatched pairs of a war-level dispute follow the dispute's side mapping when it is unambiguous: the dispute is linked to the COW war that a strict majority of its pair-decided events matched, at least `WAR_DIR_MIN_LINK = 2` of them; the war side of the MID Side A state over those events must again be a strict majority of at least 2; if that side is the war's non-initiating side the unmatched pairs are reversed (`"cow_war_dispute"`), else kept. 34 disputes are linked with an unambiguous mapping (no dispute had a split mapping); 32 unmatched pairs are reversed and 93 kept. Everything else keeps Side A (`dir_source = "sideA"`): the 3168 events of non-war disputes, 14 events of 4 war-level disputes with no pair match, 50 events of 18 disputes whose link rests on a single pair-decided event (below the minimum; with a minimum of 1 they would be 2 reversals and 48 confirmations, logged, not applied) and the 2 ambiguous pairs. In total 192 of 3720 events (35% of the war-level pairs) are reversed in 24 disputes, 160 by the pair match and 32 by the dispute mapping; the originator status, fatality and hostility codes move with the state, so `is_joiner_pair`, `war` and the fatal codings are unchanged. `events.rds` carries `dir_flipped`, `dir_source`, `dir_rule` (the reason), `war_link` (the COW war number) and `n_war_match`; `sidea1 = 0` marks a reversed row. Everything downstream (escalation flags, reference dates, choice sets, `fighting_at_ref`, the duplicate collapse, y1, the no-WWII flags, the event weights) is computed from the applied direction in every sample; no collapsed key mixes a reversed and an unreversed source. The build stops unless Germany → Poland 1939 exists and Poland → Germany 1939 does not. The appendix rebuild `V2_DIRECTION=sideA Rscript v2/R/01_build_data.R` applies the old coding everywhere and writes to `v2/data_sideA/` (its own manifest and build_log), so the two codings never overwrite each other; `02_fit_model.R --direction=sideA` (and `compare_models.R`, `run_measurement_real.R`) reads that directory and suffixes the cells with `_sideA`. * Participant-level dates (PI decision 2026-10-25, D5). peacesciencer 1.2.0 bundles `gml_part`, participant-level start and end year / month / day (the day is unknown for about 10%) for 2165 of the 2436 COW dispnums (5217 participant spells). Where the dispnum matches, `pair_dispute_intervals(part = gml_part)` dates a pair spell from its participants: entry = the later of the two participants' starts, exit = the earlier of their ends, both exact months, when each participant has exactly one gml_part spell overlapping the pair's COW years and the dates are consistent with those years (a GML entry before the pair's first COW year is clamped to January of it, since the pair was in the dispute by then; a GML exit after the last COW year to December of it; an entry after the first COW year or an exit before the last one contradicts the COW years and keeps the dispute-level bounds, as do participants with no or several overlapping spells). 5874 of the 7456 directed spells are dated this way (5634 directly, 84 with the entry clamped, 152 with the exit clamped, 4 both); 1582 keep the dispute-level bounds (774 in disputes absent from gml_part, 350 with a participant lacking an overlapping spell, 132 with several, 326 inconsistent years or entry after exit; `date_source` and `part_reason` in the interval table, counts in the build log). An unknown entry bound is also clipped by the feasible exit (688 directed spells had start_hi > end_hi under the dispute-level bounds; 216 still needed the clip after the participant dates). Before / after (dispute-level bounds / participant dates): exact entry months 5536 / 6846 and exact exit months 486 / 5988 of 7456 spells; escalations 199 / 215 (38 new, 22 dropped); undecided (event, other dispute) comparisons 230 / 71; events whose decision rests on a year-rule fallback 184 / 64; `fighting_at_ref` events 31 / 28; already-fighting (i, j, t) keys at the reference date 3687 / 3669; same-year opposite-direction pairs among the non-escalation events (both i → j and j → i in t) 118 / 113. Known limitation: comparisons stay at month resolution, and an end in the reference month counts as still active, so Israel → Egypt 1967 (dispute 1480, GML start June 29) is now an escalation of the Six-Day War dispute 1035 (GML end June 10 / 17) without a fallback, where the day fields would separate them; day resolution is an unimplemented suggestion. The statement that participant dates would need the MIDB 5.0 file no longer applies.
* Coalition expansion in stage 2 (PI decision 2026-10-25, D8; `--event_weights=dispute|none`, default `dispute`). Every A × B pair of a multilateral dispute is an event, so an initiator joining a dispute against k Side-B members contributed k softmax terms. The stage-2 part of the log density is now a composite likelihood with dispute-level weighting: event e enters as w_e · log P(j_e | n_e) with w_e = 1 / (the number of distinct targets the same initiator has in the same dispute and onset year, counted within the sample), so such an initiator-dispute-year contributes one decision's weight while targets in different disputes stay separate decisions. The build writes `w_mid`, `w_fmid`, `w_fmidcow`, `w_fmidub`, `w_war` on the pre-collapse rows (`event_weights()`), 0 outside the sample; the duplicate collapse sums a key's weights and caps at 1 (72 mid keys hit the cap). On the data (mid, before the collapse) 3517 events in 2883 initiator-dispute-years have weights summing to 2883; 2595 events carry weight 1, 358 weight 1/2, 284 between 1/3 and 1/5, 185 between 1/6 and 1/10, 95 below 1/10 (minimum 1/37, Yugoslavia → the 37 KFOR states in dispute 4343, 2000); in the war sample 479 events in 242 initiator-dispute-years, minimum 1/23. In dispute 4186 (2000) the 38 KFOR states are each a Side A initiator against Yugoslavia alone, so their events keep weight 1. `assemble_cell()` passes `w` with the events, `build_stan_data()` as `ev_w` (1 everywhere when absent, so the simulator's and the tests' calls are unchanged), and both Stan programs multiply the stage-2 log-lik terms by `ev_w`; with every weight 1 the log density equals the unweighted program (asserted against the dd48506 binaries at a fixed draw). `log_lik_stage2` stays the unweighted per-event term and the weights are saved with the fit; `stage2_loglik_R()` returns both. The joint state-year LOO and the permutation statistic use the weights; the stage-2-only LOO does not. Events that leave stage 2 (`fighting_at_ref`, target without positions) do not rescale their group's remaining weights (logged). `--event_weights=none` (cell suffix `_w1`) is the robustness comparison.
* Power levels in stage 1 (PI decision 2026-10-25, D2 and D3). W held the initiator's power CHANGES but no LEVELS, so a "capable states initiate more" effect could flow into μ0 through the inclusive value. The build adds `M_lvl` and `R_lvl` to the panel, the within-year centred log CINC share and log PageRank at t − 1 (centred over every state with positions in that year, the same set the gap scale uses, so the reference does not depend on h) divided by the gap constants 3.268213 and 0.523567, so their units match the gap axes (0 = the system-average level that year; SD 0.66 and 0.93 over the state-years; `assemble_cell()` leaves them uncentred, unlike the other controls). They enter the main W only, not X (an open PI question). D3 adds the centred log system size at t − 1 (`log_n_system_tm1`, already in the panel) to the main W: the IV grows with the number of alternatives, so τ · IV carried a system-size trend. `assemble_cell()` logs, per cell, the correlation between the IV at a null point (μ = 0, Σ = I, b = γ = 0) and `log_n_system_tm1`, and the R² of that IV on W without and with the new column. Main W = `dM_i`, `dR_i`, `M_lvl`, `R_lvl`, `ongoing_tm1`, `log_prior_mids`, `dem_tm1`, `log_n_system_tm1` (P1 = 8); `--full_controls` is unchanged (exactly 8bf0ce1).
* Events (PI decision 2026-10-24, joiners in the main specification). An event is a Side A participant → Side B participant pair of a COW-MID dispute, joiners included, with onset year equal to the first year that pair appears in the dispute (the sides are those of that earliest year; `build_pair_table()`, P3 fix 2026-10-25: France and the USSR are opposed in dispute 258 in 1939 and again with reversed sides in 1941, the only such pair), one direction per dispute pair, and every A × B pair of a multilateral dispute is an event. For war-level disputes linked to a COW war the direction then follows COW's war initiator (see "Initiator direction"). `INCLUDE_JOINERS = TRUE` is the main build (FALSE reproduces the originator-only base of 2770 events). With joiners there are 3720 events, of which 950 are joiner pairs (`is_joiner_pair`, TRUE when either side has `orig = 0`; kept for tabulation, never a covariate). The war sample grows most, from 127 originator pairs to 552 pairs, because the two world wars contribute most of their pairs through joiners. The fatal-MID rules of 2026-10-23 apply unchanged to joiner pairs (with the pair-level war coding of 2026-10-24 the joiner pairs are coded cow 897, mic_fill 50, uncoded 3; the war rule no longer adds any).
* Ongoing disputes (PI decision 2026-10-24, month resolution since the second decision of that day). Stage 2 is target selection, so a new dispute against a state the initiator is already fighting is escalation, not selection. An event is an escalation when i and j are both participants in a different dispute that started before the event's dispute start date and had not ended by it, compared at month resolution. The year-level version of this rule (pair in a dispute active in year t with onset before t) mislabelled about 45% of the escalations (China → USA 1950, the Korean War, was dropped because a short 1949 incident had a 1950 row) and missed re-entries within a year. The fallback dates come from `cow_mid_disps` and are dispute-level, because that table ships the dispute start month and year (`stmon`, `styear`) and the duration in days (`mindur`, `maxdur`) but no end month and no participant-level dates (`cow_mid_dirdisps` has years only); participant-level months come from `gml_part` where available (D5, below). The end date is therefore a bound, not a point, between the first day of the start month plus `mindur` and the last day of the start month plus `maxdur`, clamped to the dispute's last year in the directed dispute-years (198 of 2436 disputes have an exact end month, 1954 a two-month span, 284 wider, 10 inconsistent with the duration and given the whole last year). A pair that enters a dispute after its first year has an unknown entry month (the whole year), a pair that leaves before the dispute's last year an unknown exit month, and a pair that leaves and re-enters has separate spells. Every comparison is three-valued. When it is undecided the year rule decides and the fallback is counted. Across the 43,874 (event, other dispute) comparisons 176 are undecided (80 because the event's own pair entered its dispute after the dispute's start year, 35 because the other dispute's pair entered late, 61 because the end bound straddles the event month); 143 of 3720 events have a decision that rests on a fallback. Result 217 escalations under the month rule against 288 under the year rule (106 no longer escalations, 35 new ones; 60 joiner pairs, 157 originator pairs). Escalations stay in `events.rds` with `escalation = TRUE` (`escalation_year` keeps the year rule, `esc_fallback` marks fallback decisions, `ev_start_lo` / `ev_start_hi` the event's date interval as a month index) and are excluded from every sample flag, so they are in neither stage 2 nor y1. For choice sets each state-year (i, t) has TWO sets since the Codex review of 2026-10-24 (P1-1, PI choice "A′"). The stage-1 IV set drops alternative j when i and j are in a dispute active at January of t that started before it, for every state-year alike, so the stage-1 regressor IV_n uses no information about the state-year's own events (the previous rule used the event date for initiators and January for non-initiators, which made the IV set a function of y1). The stage-2 set drops j when i and j are in a different dispute active at the state-year's reference date, the start of its earliest non-escalation event when it initiates and January of t otherwise, that started before it (unchanged). Both rules are the month rule with the year fallback, and nothing after the respective date enters. For a non-initiating state-year the two sets are identical. The alternatives files keep one row block per state-year, the union of both sets, with the flags `in_iv` and `in_s2` (`choice_set_flags()` in `00_helpers.R`); rows in neither set are removed. At h = 3 the IV rule drops 3724 of 1.72 million rows and the stage-2 rule 3582; 3501 rows are in neither set and leave the file, 1,720,058 remain, of which 81 are IV only and 223 stage 2 only; 229 of the 2096 initiating state-years have different sets (before the P1-2 joiner fix below these were 249 of 2165 initiating state-years, 130 IV-only and 226 stage-2-only keys, as the review reported). Escalation flags are event-date based and unchanged. Because the stage-2 set is fixed at the reference date, a later event of the same state-year whose pair was still fighting at that date (their dispute ended between the reference date and the event) has no stage-2 row (it may keep an IV-only row with `in_s2 = 0`). There are 31 such events (29 after the duplicate collapse; 7 in fmid, 1 in war), flagged `fighting_at_ref`. They keep every sample flag, so y1 is unchanged, and leave stage 2 only, like events whose target lacks positions; the build lists them and stops if any other non-escalation event loses its stage-2 row. This is a deviation from the requirement that every non-escalation event's chosen alternative be in its choice set, which cannot hold with one stage-2 set per state-year, and is flagged for the PI. The build logs the escalation and alternative counts under both rules with examples, asserts that the IV flag equals the January rule on every retained row and that only initiating state-years have differing sets, and stops if any state-year with rows has an empty IV set or any initiating state-year a stage-2 set that is empty or holds only its chosen target (`assemble_cell()`, `build_stan_data()` and the Stan programs repeat these checks). Helpers `dispute_date_bounds()`, `pair_dispute_intervals()`, `month_rule()`, `flag_escalations_month()`, `reference_dates()`, `already_fighting_keys_month()` (reference `NULL` = January for every state-year) are in `00_helpers.R` and unit-tested on toy disputes (ended before the new start in the same year, still active, undecided month, and a regression fixture in which adding or moving a state-year's events changes its stage-2 set but never its IV set). Since 2026-10-25 the participant-level dates of `gml_part` replace the dispute-level bounds wherever the dispnum matches (see "Participant-level dates"); the dispute-level bounds described here remain the fallback.
* Joiner entry month (Codex review P1-2, 2026-10-24). A pair with a joiner on either side (`orig == 0`) whose spell begins in the dispute's first year used to receive the dispute's exact start month although the joiner's entry month is unknown. Its entry interval is now [dispute start month, December of that year] with `start_exact = FALSE`; originator pairs keep the exact start, later entrants keep the whole entry year. Undecided comparisons fall back to the year rule as before. On the COW data 1154 of 7456 directed spells (577 undirected pairs) are affected; escalations fall from 217 to 199 (18 no longer escalations, 0 new), and the events whose decision rests on a fallback rise from 143 to 219. The build rebuilds the pre-review intervals only to log these before / after counts.
* Same-year duplicates (PI decision 2026-10-24). After the escalation exclusion, events with the same (initiator, target, year) from different disputes collapse into one event (`collapse_duplicate_events()`). Sample flags and fatality codings are ORed, `dispnum` keeps the smallest dispute number, `dispnums` lists them all, `n_disputes` counts them, `is_joiner_pair` is FALSE when any collapsed row was an originator pair, and escalation rows are untouched. With the review fixes 188 rows in 93 keys collapse into 93 events (mid 3521 → 3426, fmid 1167 → 1153, fmidcow 990 → 983, fmidub 1189 → 1172, war 478 → 469), so the likelihood sees one chosen alternative per (i, j, t), asserted in the build and in `assemble_cell()`. The no-WWII sample flags `in_<sample>_noww2` (Codex review P2-3) are the sample flags of the non-WWII source rows alone, ORed in the same collapse, so a key that mixes a WWII and a non-WWII dispute stays in the `--drop_ww2` sample only when a non-WWII dispute qualifies, and its fatal / war coding there comes from the non-WWII disputes only. One collapsed key mixes the two (UK → Bulgaria 1941, disputes 258 and 3871): it stays in the no-WWII `mid` sample and leaves the no-WWII `fmid` and `war` samples; the other five collapsed WWII keys are WWII-only and leave all of them.
* WWII (appendix option `--drop_ww2`, cell suffix `_noww2`, not in the main grid). `is_ww2` marks the events of 16 COW-MID disputes, 258 (the Second World War itself) plus every war-level dispute that starts between 1939-09 and 1945-09, whose highest action is 21 (join interstate war) and whose dyad appears in COW inter-state war 139 in `cow_war_inter` (235, 339, 414, 418, 518, 2725, 3701, 3705, 3717, 3724, 3813, 3820, 3822, 3826, 3827, the run-ups to a state's entry into the war). Disputes 157, 179, 183 and 613 are wars of their own (COW wars 130, 142, 136, 145) and stay. The rule is `ww2_disputes()` in `00_helpers.R`, the list is asserted against `WW2_DISPNUMS`, and the build log prints every candidate with its reason. 134 of the war events are WWII; `--drop_ww2` removes them from stage 2 and their initiations from stage 1 using the `in_<sample>_noww2` flags (above), so a state-year whose only events were WWII gets y1 = 0.
* Samples: `mid` (all), `fmid` (fatal, main coding), `fmidcow` (fatal, COW-only coding; appendix), `fmidub` (fatal, upper bound; appendix), `war` (pair-level war, at least one participant at hostility level 5).
  * War is coded at the pair level (PI decision 2026-10-24, revised the same day). An event is a war event only when the dispute is war-level (hostility level 5) and at least one participant of the pair reached hostility level 5 itself (participant `hostlev1` / `hostlev2` in `cow_mid_dirdisps`, maximum over the pair's years). The dispute-level coding is kept as `war_disp`. Of the 552 dispute-level war pairs 508 are war pairs (44 had neither participant at level 5, mostly peripheral Gulf War and Iraq 2003 coalition members); after the escalation exclusion the war sample has 476 events instead of 520, and after the duplicate collapse 467, with a WWII share of about 28%. A first version required both participants at level 5 (329 events); the PI chose the less strict rule. The war rule in the fatal coding uses the pair-level definition and adds 29 events.
  * COW fatality: an event is fatal if either side's fatality ≥ 1 or the dispute fatality ≥ 1; negative codes → missing. 229 of 2,770 events have every COW fatality code missing.
  * `fmid` (PI decision 2026-10-23) applies four rules in order. (a) Wars are fatal by definition, since COW wars require 1,000+ battle deaths. With the dispute-level war coding this added 20 events, 14 with missing COW fatality and 6 that COW codes as non-fatal (MIC codes 5 of the 20 as non-fatal and omits 11; the war rule takes precedence); with the pair-level coding of 2026-10-24 it adds none. (b) A coded COW fatality value is kept as is. (c) When every COW code is missing, the event takes the MIC 1.0 value (Gibler et al., Militarized Interstate Confrontations; confrontation-level `fatalmin` ≥ 1; MIC `micnum` = COW `dispnum`). MIC fills 182 events (112 fatal, 70 non-fatal). (d) When COW and MIC are both missing, the event takes the GML MID 2.2.1 coding of the same directed pair (Gibler, Miller and Little 2016; peacesciencer `gml_mid_ddydisps`; same rule as COW). GML codes 11 of the remaining 33 events (5 fatal, 6 non-fatal). 22 events are coded by no source and stay non-fatal. Result 632 fatal events (495 under COW only). `fatal_source` in `events.rds` records which rule set each event.
  * No source overrides an earlier coded value (COW, then MIC, then GML). Where both code fatality they disagree on 120 events, which the build logs but does not use. MIC also omits 700 of the 2,770 COW events and recodes Side A for some disputes; the event base and sides stay COW.
  * `fmidcow` is the earlier rule (missing → not fatal, no war rule) and reproduces the pre-2026-10-23 `fmid` exactly.
  * `fmidub` is the bounds check. It equals `fmid` plus the 22 events no source codes, counted as fatal (654 events). If `fmid` and `fmidub` results agree, the uncoded events do not drive the fatal-MID findings.
  * MIC source file `data_raw/mic-conf-1.0.csv` is checked against a sha256 in `00_helpers.R` (`MIC_CONF_SHA256`); see `data_raw/SOURCE.md`.
* Positions (PI decision 2026-10-23, replacing the within-year standardisation of 2026-10-22). M = log CINC share and R = log IGO PageRank, both left in raw log units. CINC share and PageRank each sum to one over the system in a year, so M is the log share of world capabilities and R the log share of network centrality. The stage-2 gaps x_ij = (M_i − M_j, R_i − R_j) are therefore log ratios between the two states. The two axes have very different spreads (SD about 3.27 log points for M and 0.52 for R), so each gap is divided by one constant per axis, the same for every year, lag and choice-set variant (PI decision 2026-10-23, option 1). The constant is the SD of the within-year gap over all ordered pairs of distinct states (`gap_scale()` in `00_helpers.R`), 3.268 for M and 0.524 for R, stored in `change_scale.csv` with h = NA and the raw log ratios kept as `dM_logratio` and `dR_pr_logratio`. One model unit on the material axis is therefore a 26-fold ratio of CINC shares, and on the relational axis a 1.7-fold ratio of PageRank. No script converts estimates back. To read a μ, Σ or r0 value in log ratios, multiply it by the constant for its axis in `change_scale.csv` (rows with h = NA) by hand; `03_extract.R` and `typology.R` report in the scaled units. The build stops and lists any state-year with a zero or missing CINC share, and likewise any non-finite or non-positive PageRank, instead of flooring it (none exist; smallest share 2.4e-7, smallest PageRank 7.8e-4). PageRank weights are shared IGO memberships with isolates included as vertices. The eigenvector centrality `R_eig` is unchanged (still standardised within year); it is not used in the main grid and the eigenvector robustness run is unscheduled. Years with all-missing IGO data are dropped and listed in `build_log.txt` (`IGO_FILL = "drop"`; `"locf"` carries the latest IGO year forward). With peacesciencer 1.2.0 no year is all-missing (1990 is partially missing and its NA dyads are treated as no shared membership). Why the change. On within-year z-scores a state's change over [t−1−h, t−1] moved with the growth of the system (correlation with the 3-year log growth in the number of states about +0.29 for M and +0.17 for R at h = 3), and the changes had SD 0.11 and 0.25, so the per-unit priors on β and α dominated the data.
* Changes (same decision). One state-level table per lag, `changes_lag{h}.rds`, built by `build_change_table()` in `00_helpers.R`. For every state in the system at t with positions at t−1 and t−1−h, the raw change is d = level(t−1) − level(t−1−h) in log units (calendar joins, kept as `dM_raw_h`, `dRpr_raw_h`). The transformed change `dM_h`, `dRpr_h` subtracts the mean raw change of all states that have a change in that year and divides by one pooled constant per lag and variable, the SD of the year-centred change over all rows of that lag. A value of zero means the state changed like the average state over the same window, and the units are pooled SDs (1 unit = 0.19 log points for M and 0.15 for R at h = 3; the constants are in `data/change_scale.csv`, in the manifest notes and in the build log). The same table supplies the initiator's change in stage 1 (dM_i, dR_i in W and X) and the target's change in stage 2. The build asserts finiteness, within-year mean 0, pooled SD 1, and |cor| < 0.02 between the transformed change and the 3-year log growth in the number of system states (the correlation is 0 by construction because the growth variable is constant within a year), and logs the raw and transformed correlations.
* Target changes in stage 2 (same decision). The alternatives files carry the target's transformed change `dM_j_h`, `dRpr_j_h` joined from the same table, and `z_columns()` includes both in Z for every model, the 1-D ones included. A target with no change value (no position at t−1−h, typically a recent entrant) gets 0 and `dch_j_missing = 1`; at h = 1, 3, 5, 10 this affects 21k, 62k, 99k and 185k of about 1.6–1.8 million alternative rows (220, 652, 1069 and 2063 target state-years). `assemble_cell()` adds `dch_j_missing` to Z only when it is non-constant in the assembled cell and logs that decision; `dM_j_h` and `dRpr_j_h` are centred over the assembled alternative rows like the other continuous Z columns, and the indicator stays 0/1 like the other dyadic indicators.
* Timing: positions at t−1; changes over [t−1−h, t−1]; dyadic controls (contiguity, ATOP defense/offense alliance, joint democracy polity2 ≥ 6, major-power count) at t−1; all via calendar joins.
* Conflict history: monadic and dyadic MID onset counts in the 10 years before the window starts, dyadic and monadic peace years as of window start, counted over every participant including joiners (consistent with the events; `INCLUDE_JOINERS` governs both). The main spec includes the two counts (`--conflict_history=TRUE` in `02_fit_model.R`), which enter as `log1p()` and are centred. The dyadic peace years left the main Z on 2026-10-24 and the monadic peace years left the main W later that day (see W / X / Z below); `--full_controls` restores the monadic ones.
* Lagged involvement at t−1 (PI decision 2026-10-24), always from every participant including joiners. `ongoing_tm1` (stage 1) is 1 when the state was in any MID active in year t−1 (mean 0.31 at h = 3). `dy_mid_tm1` (stage 2) is 1 when i and j were both in a MID active in t−1. After the already-fighting cut a remaining alternative can have `dy_mid_tm1 = 1` only when every dispute of the pair active in t−1 had ended by t, or when the row is a chosen event of a new dispute. At h = 3 it is 1 on 5938 of 1.72 million alternative rows and on 790 of 3300 usable mid events (56 of 487 war events). `assemble_cell()` stops if it is constant in a cell.
* Democracy and alliance NA → 0 with `*_missing` indicator columns kept in the data (not in the default spec).
* Choice sets: `all` = every other system member at t with positions at t−1, minus the already-fighting alternatives; `polrel` = the same restricted to contiguous (conttype 1–5) or either state a COW major power. Events whose target is outside the choice set are dropped from stage 2 (logged; the initiator's y1 stays 1).
* Control sets (PI decision 2026-10-24, minimal controls; levels and system size added 2026-10-25, see "Power levels in stage 1"). Major-power status and alliance are components of material and relational power, so they are bad controls and left the main specification, and the main sets are as small as the design allows. Main W (stage 1) = initiator power changes dM_i, dR_i, the power levels `M_lvl`, `R_lvl`, `ongoing_tm1`, log1p monadic prior MIDs, democracy `dem_tm1`, the centred log system size `log_n_system_tm1` (P1 = 8). Main X (the μ shifters) = dM_i, dR_i only, no monadic controls (P = 2). Main Z (dyadic) = land contiguity, joint democracy, log1p dyadic prior MIDs, `dy_mid_tm1`, the target power changes dM_j_h and dRpr_j_h, plus `dch_j_missing` when it is non-constant in the cell (Pz = 6 or 7). `--full_controls=TRUE` (cell suffix `_fullctrl`) reproduces exactly the base specification of commit 8bf0ce1 (Codex review P2-4; `git show 8bf0ce1:v2/R/assemble_cell.R`), same columns in the same order. W = X = `dM_i`, `dR_i`, `cowmaj_tm1`, `dem_tm1`, `log_prior_mids`, `log_peace_years` (P1 = P = 6; the last two follow `--conflict_history`). Z = `contig_land` (`--contiguity`), `alliance_def_off`, `joint_dem`, `major_count`, `log_dy_prior_mids`, `log_dy_peace_years` (both follow `--conflict_history`), `log_capdist` (`--distance`), `dM_j_h`, `dRpr_j_h`, `dch_j_missing` when non-constant (Pz = 8 or 9). The base had neither `ongoing_tm1` nor `dy_mid_tm1`, which postdate 8bf0ce1, so they are absent under `--full_controls`; `--dy_peace_years` adds nothing there when `--conflict_history` is on and restores the dyadic peace years at the base position when it is off. The lists live in `assemble_cell.R` as `w_controls()`, `x_controls()` and `z_columns()`, each taking `FULL_CONTROLS`, and are tested against the lists evaluated from the base commit itself; `benchmarks.R` takes its Z from `z_columns()` and the gap regression's X from `x_controls()`, and uses the stage-2 rows (`in_s2 = 1`) of the alternatives. Every monadic control that enters W or X is centred in `assemble_cell.R` (0/1 indicators included); dM_i, dR_i and the levels M_lvl, R_lvl are not (zero power change and the system-average level stay the reference). α0 (stage 1) is the log-odds at zero power change and sample-average controls; in the main spec μ0 is the ideal gap at zero power change, under `--full_controls` at average controls as well. `x_ref` for `mu_state` = mean X over initiating state-years in the sample (length 2 in the main spec). `dy_mid_tm1` stays 0/1 like the other dyadic indicators. `SY_INDICATORS` lists the three 0/1 monadic indicators the build writes.

* Fit provenance (audit 2026-10-24; Codex review P2-5). `02_fit_model.R` reads `manifest.csv` and `git rev-parse HEAD` before the data are assembled and passes that manifest snapshot into `assemble_cell(manifest = ...)`, which checks every input file's nrow and sha256 against the snapshot at load (`assert_matches_manifest()` takes a path or a data.frame), so a rebuild between the snapshot and the load stops the run. It reads the manifest again just before saving and stops without saving if any digest changed while sampling, re-checks the three cell files on disk against the digests read at load, and records in `args` the commit at load and at save, whether `v2/R` or `v2/stan` had uncommitted changes, the manifest build time, `SLURM_JOB_ID` and `SLURM_ARRAY_TASK_ID` (NA when unset), and the start and save times. If the manifest or the cell files changed while sampling, the fit is saved as `fit_<cell>_STALE.rds` with the mismatch in `obj$stale` instead of being discarded, and the downstream tools read it only with `--allow_stale=TRUE`; `compare_models.R` treats an unreadable fit file as missing with a log line. `run_measurement_real.R` and the `measurement_tests.R` CLI also check that the fits score exactly the assembled cell (`assert_fit_matches_cell()`: E, N1, S, W / X / Z columns, event identities, weights; C4) and reject `--sampled_m` (C5).

## Identification and estimation decisions

* Only Σ⁻¹ and Σ⁻¹μ are identified by the choice data (the −½ μ'Σ⁻¹μ term is constant across alternatives), so μ is recovered as Σ(Σ⁻¹μ); this is automatic in the parameterisation.
* The "a" model fixes corr(a_i1, a_i2) = 0 but keeps corr(c, a1) and corr(c, a2), parameterised so Ω is always PD (r2 = q·√(1−r1²)).
* AME: V column-centred (a column constant cancels in the softmax); the anchor block of U (K states with most initiations) is lower-triangular with positive diagonal; U/V scale is fixed by N(0,1) priors only. Procrustes alignment across chains in `03_extract.R` is a safety net and its rotation deviation is logged.
* Priors: μ0 ~ N(0, 2) per element (`prior_mu0_sd` is data, 2 from `build_stan_data()`), β ~ N(0, 1) per element (`prior_beta_sd` is data), σ_x ~ lognormal(0, 1), sd of random effects ~ half-N(0, 1), LKJ(2) on the 3×3 correlation of (c, a_1, a_2) in the b models and its restriction to corr(a_1, a_2) = 0 (the disk density ∝ 1 − r_1² − r_2²) in the a models, (ρ + 1)/2 ~ Beta(2.5, 2.5) on Σ's correlation (explicit since 2026-10-25; before that the implicit uniform of the bounds), (r + 1)/2 ~ Beta(2.5, 2.5) on corr(c, a) in the one-dimensional models, γ, α ~ N(0, 1), τ ~ N(0, 1), α0 ~ N(0, 2.5). The μ0 and σ_x scales were chosen when x had SD about 1.4 per axis. After the gap scaling x has SD about 1 per axis, so these priors keep roughly their intended weight.
* Main specification = the full all-states choice set, `--variant=all --sampled_m=0` (the defaults of `02_fit_model.R`); `polrel` and `--sampled_m` remain options for robustness and pilots. Sampled alternatives (`--sampled_m=m`) are an option with two outcome-separated samples. (a) IV rows, for every state-year, m alternatives drawn uniformly without replacement, ignoring outcomes, with IV = log-sum-exp + log(n_full/m); this estimate of the log partition sum is downward biased by Jensen's inequality, equally for initiating and non-initiating rows, and the bias shrinks with m. (b) Event rows, each event gets its own set of its chosen target plus m uniform others, independently per event, so the conditional-logit score is unbiased (McFadden 1978). Unit tests in `tests/testthat/test_sampled_alternatives.R` reproduce the review cases.
* Seed 123 everywhere.

## Typology outputs

Main output (`typology_<cell>.csv`): the 5-bin classification of posterior μ_i at `x_ref` with radius `r0` (default 0.5 in scaled gap units, i.e. 0.5 × 3.268 log points, about a 5-fold CINC ratio, on the material axis and 0.5 × 0.524, about a 1.3-fold PageRank ratio, on the relational axis; peer = within r0 of the origin; bully (+,+), challenger (−,−), hybrids off-diagonal). For 1-D models the single axis gives weaker / peer / stronger (μ > r0 means the state targets others positioned below it on that axis).

`theta_lo` / `theta_hi` are a circular 90% interval (deviations unwrapped around the circular mean, bounds wrapped to (−π, π], `theta_width` the arc length; P3 fix 2026-10-25, plain quantiles of atan2 gave a near-full-circle interval for a cloud straddling ±π). One-dimensional cells carry an `axis` column in `typology_` and `mu_state_` (B2).

Appendix outputs, written by `03_extract.R` as well. (a) `typology9_<cell>.csv`, a 9-cell classification with a peer band on each axis (`--band_M`, `--band_R`, default r0): bully, challenger, peer, material / relational opportunist, material / relational challenger, compensator A (M down, R up), compensator B (M up, R down), with posterior cell probabilities and the modal cell; D = 2 only. (b) `reach_<cell>.csv`, posterior mean and 90% interval of r_i = ||μ_i|| and of |μ_i1|, |μ_i2|. (c) `focus_sigma_<cell>.csv` and `focus_states_<cell>.csv`, descriptive only: the single pooled Σ (SDs, correlation) and each state's empirical dispersion of its chosen targets' positions around the posterior mean μ at the event (SD per axis, correlation, n_events; fewer than 5 events flagged unreliable). The model has one pooled Σ; a state-varying Σ_i would be a model change for the PI to decide on, not something these files estimate.

## Within-chain parallelism (reduce_sum)

Both programs evaluate the likelihood as `reduce_sum_static` over state-years (stage-1 term, IV log-sum-exp and the state-year's stage-2 events in one slice; `grainsize` is data, N1 for one slice = the exact serial sum). `02_fit_model.R --threads_per_chain=k` sets `rstan_options(threads_per_chain)` and `grainsize ≈ N1 / (4k)`; request `cpus-per-task = chains × k` (08_main_grid.sbatch and 04_pilot.sbatch default to 8 threads per chain, 32 and 8 cpus, 4 GB per cpu). rstan 2.32 compiles with `-DSTAN_THREADS` by default and `compile_models.R` asserts it. Generated quantities are serial, so `log_lik` is identical across thread counts; the log density and gradient agree to 1e-10 / 1e-8 (tests/testthat/test_reduce_sum.R). Profiling on the 40-state simulated cell puts ~99% of the gradient in the utility computation over alternative rows (`sim/results/profile_breakdown.csv`); on this 2-core container 2 threads gave 2.1–2.4× and 4 threads (oversubscribed) 2.7–2.9× (`sim/results/threads_timing.csv`); the Roar curve must come from the pilot. Stan `profile()` sections are in both programs for CmdStan users. Compiling M2 needs about 3 GB with `v2/env/Makevars` (no `-g`, aggressive GC) versus >5.7 GB with R's default flags; copy it to `~/.R/Makevars` where memory is tight.

## Tests

`Rscript v2/tests/run_tests.R` (needs compiled models for the likelihood test; `V2_REF_BUILD` pointing at a directory with `<model>_3a9e7d0.rds` and `<model>_dd48506.rds` enables the equivalence tests against the earlier programs, which pass with the known prior shift of 2026-10-25 and with every event weight 1). `Rscript v2/sim/run_sim.R`, `Rscript v2/sim/run_sim_1d.R` and `Rscript v2/sim/run_measurement_tests.R` are the simulations (current-model world since 2026-10-25); `sim/SIM_REPORT.md` reports the OLD world and is superseded until `slurm/10_simulations.sbatch` has run and `write_sim_report.R` is rerun.

Measurement tests (review 2026-10-25). LOO comes in three labelled flavours, stage 2 (the target choices), stage 1 CONDITIONAL (the Bernoulli term alone, with the state-year's events staying in) and the JOINT state-year LOO (log_lik_stage1[n] plus the weighted sum of the state-year's log_lik_stage2, so a left-out state-year loses its initiation and its choices; B1); `compare_models.R` reports all three. Holdout hits are the per-draw indicators that the chosen target ranks first / in the top 5 (`hit1_pdraw`, `hit5_pdraw`) and, labelled separately, the rank of the chosen target's posterior-mean probability (`hit1_pmean`, `rank_pmean`); the mean rank is no longer thresholded (B6). The permutation test in `refit` mode scores observed and permuted data by the same procedure (the stage-2 LOO elpd of refits) with p = (1 + exceedances) / (1 + n_perm); `rescore` mode rescores the original fits and is a reliance diagnostic, not a calibrated p-value (B7). The measurement-error check inflates the relational LEVEL of flagged state-years and rebuilds the gaps, both window endpoints of the initiator and target changes (with the year-centring and the pooled SD) and the level column (`perturb_relational_levels()`; B8). The temporal holdout freezes the pooled constants (gap constants from the positions up to the cutoff, change SDs, W / X and Z centring, x_ref) on the training years and applies them to the test years (`freeze_preprocessing()`; B9). The benchmark's "CINC ratio" is plogis(M_i − M_j) from the raw log material gap (B10).
