# Independent review of the multiverse loop

19 November 2026. **Do not launch the full loop as packaged.** It has a definite window-validation blocker and unsafe restart semantics. Several earlier fixes are implemented, but the new escalation and timing analyses need narrower interpretations.

## Scope and verification

Reviewed the contents of `/Users/jarededgerton/Downloads/targeting_multiverse.zip` directly, without extracting or executing the repository. Locations below are paths and one-based line numbers **inside that archive**, under `targeting_multiverse/`.

Read: `README.md`, `docs/PROMPT_gpt_review_loop.md`, `docs/decisions.md`, `config.sh`, `run_all.sh`, all eleven numbered R scripts, and all 201 IDs in `inputs/phaseA_specs.txt`. The eight supplied logs were parsed for classifications, outcomes and dump diagnostics. `R/01_build_layers.R` and `R/05_dump_events.R` were also compared in full against the previously audited scripts; `R/02_build_positions.R` and `R/lib/helpers_data.R` are byte-identical to their previously audited counterparts. For the other four libraries (`spec.R`, `assemble_cell.R`, `helpers_model.R`, `opp_weights.R`), inspection was targeted to configuration, assembly, event/weight indexing and the called analysis paths; this is not an exhaustive audit of their unrelated model families.

Checks performed: Python archive/source inspection, full ID-list uniqueness check, source comparisons, and `bash -n` on both shell files through standard input. Both shell files pass syntax checking. **No R script or analysis pipeline was run.** The ZIP and source files were not changed; this report is the only file written. External RDS inputs, reused positions, raw network files and the event-data builder are not supplied, so I cannot certify numerical rebuilds or the original construction of fatality membership.

## A. Ranked findings

### P1 — blockers or paths to wrong/stale results

1. **The requested 0–6-month loop stops at window 4.** `R/05_dump_events.R:67–68`; `config.sh:23`; `run_all.sh:69`.

   The dump script still requires `COORIG_W %in% c(0L,1L,2L,3L)`. The configured loop asks for 0,1,2,3,4,5,6. On a fresh run, the window-4 dump stops before the multiverse sweeps begin. The supplied 0/1-month smoke logs cannot catch this. **Minimal fix:** extend the validated domain to the intended 0:6 and check every configured window in a preflight. This is a static, definite failure; no R execution is needed to establish it.

2. **`TEST=1` contaminates the production cache.** `run_all.sh:19–24, 48–57, 85–94, 143–152`.

   Test and production runs write to the same `output/`. Test mode saves validation for only one positions file, a two-measure random set, and 20-draw bootstrap/permutation CSVs. A subsequent production run skips those nonempty files. Production can therefore retain the wrong validation universe, bootstrap only two random measures, and keep resampling outputs that fail the reporting gate. Test sweep CSVs also remain next to production CSVs; the recursive summarizer can count an overlapping main measure twice.

   **Minimal fix:** give test mode a separate output root, and refuse production reuse of test artifacts. Check expected spec IDs, validation-universe size and requested B before accepting a cached result. Do not describe the mechanics check as safely resumable into production.

3. **Restart markers do not certify the inputs or successful analyses.** `run_all.sh:24, 29, 34–44, 76–81, 98–101, 134–152`; `R/07_fit_sweep.R:328–347`.

   Markers hash only dump basename, positions basename and options—not contents, code, configuration, package versions or upstream provenance. Variant filenames such as `var_aggr.rds` do not even encode the main window. Changing the main window/specification, replacing positions, changing `DATA_ENTRY`, or correcting code can silently reuse old variants/results. Existing `data_entry` and positions symlinks are not checked against the requested new destinations. A nonempty partly written CSV is also accepted by `done_or`.

   Separately, the sweep converts candidate exceptions into `ERROR` rows and exits successfully; the shell then touches its completion marker. `LOOP_DONE` can consequently describe an incomplete/error-containing sweep that subsequent restarts skip. The positions checksum command suppresses failure with `|| true` and does not compare against an expected manifest. Rebuild mode's `ls ... positions_core_*` accepts a partially completed weighting family, then the global count check stops rather than repairing it.

   **Minimal fix:** fingerprint code, arguments and input bytes in a run manifest; validate that fingerprint and all expected outputs before reuse. Write results atomically and record explicit completed-with-errors versus complete status. Do not mark an analysis complete when required candidate fits have unhandled errors. Check each expected positions file and its source manifest. Reusing unchanged core/IGO transformations is reasonable, but dates and file counts alone do not establish that the reused bytes are the right ones.

4. **The initiating-side fix reads a collapsed side flag that need not belong to the primary dispute.** `R/05_dump_events.R:282–288`; `R/lib/helpers_data.R:435, 445, 472–478`.

   Rule 1 groups `events.rds$sidea1` by its primary `dispnum`. But duplicate-event collapse sets `dispnum=min(source IDs)` while setting `sidea1=all(source sidea1==1)`. That is a composite Boolean, not necessarily the initiator's side in the primary dispute.

   **Concrete failure scenario:** one originator-originator event key has primary dispute 100 with initiator Side A=1 and secondary dispute 200 with initiator Side A=0. Collapse retains dispute 100 and `sidea1=0`. If this is the only usable originator event for dispute 100, rule 1 infers initiating Side B and reverses its joiner labels. Matching both actors to primary-dispute originator flags does not repair the side value. Likewise the collapsed maximum `war_link` is not guaranteed to describe the primary dispute used by fallback rule 2.

   **Minimal fix:** infer the dispute map from uncollapsed, dispute-specific directed originator events, or carry the primary source's side and war link explicitly. Audit mixed-source cases separately. The logs establish that mixed-source events exist—33/1,080 fatal events and 76/3,276 all-MID events—but the package lacks the RDS rows needed to count actual misclassifications. The regression checks on 13 disputes do not rule out this general failure.

### P2 — analyses or reporting that can mislead

5. **Step B has not constructed a prospective “turns fatal” outcome.** `R/05_dump_events.R:452–458`; `R/07_fit_sweep.R:202–226`; `R/lib/assemble_cell.R:615–620, 837–845`.

   It regresses membership of an existing event in the fmid sample on the chosen row's covariates. Its unit is a retained directed pair-entry event, including later joiners, not one initially nonfatal dispute followed forward. There is no first-fatality date, check that the dispute is nonfatal at entry, or subsequent observation period. A state joining an already deadly war is included with network positions/type measured after conflict and potentially after fatality began. Multiple entries can repeat the same underlying dispute outcome. A collapsed key's membership can also come from a secondary source dispute.

   **Minimal fix:** for a fatal-escalation test, define one explicit at-risk unit, measure predictors before its risk starts, and obtain the subsequent fatality outcome and exposure/censoring. Exclude already-fatal disputes at that reference. If retaining this implementation, call it a weighted association between entry-event characteristics and fatal-sample membership, conditional on stage-2 eligibility. The supplied missing event builder prevents verifying that `in_fmid` equals any particular dispute-level eventual-death definition. The 1,080/3,276 membership count is coherent with the logs; it does not validate the transition interpretation.

6. **Step B's surface test is not a test of no type difference in fatality.** `R/07_fit_sweep.R:207–224`.

   B0 and B1 both contain `ty_*` intercepts. `surfaces_differ` tests only the 5(G−1) gap-coefficient restrictions, not the type intercepts. The reported 10-df p=0.35 therefore permits different baseline fatality probabilities by type. It also does not establish equality of surfaces, or distinguish selection from failed bargains causally. **Minimal fix:** label the null exactly, export the intercept contrasts, and add a joint intercept-plus-surface test if asking whether type predicts fatality at all. Show predicted risks over common support. Keep target choice and escalation on their respective scales; their coefficient sizes are not directly comparable.

7. **The event study is aligned to pair entry, not dispute onset.** `R/10_event_study.R:5–12, 35–38, 103`; `run_all.sh:150–152`.

   The code explicitly uses `D$yr`, although the proposed question and plot call this the dispute year. For a joiner entering in 1995 into a dispute begun in 1990, k=−3 is 1992—already two years into the dispute. A “pre-event” decline can thus be a consequence of ongoing conflict. The balanced −10/+5 panel additionally conditions on future state survival/coverage and excludes the last five event years; this changes both cases and comparison alternatives. It is a descriptive contrast against the risk-set mean, not a matched or controlled event study.

   **Minimal fix:** export both true dispute-onset and entry dates and present both alignments. For punishment/anticipation, add an independently dated first threat/recruitment reference where available. Publish excluded cases and pre-only versus balanced-panel sensitivity. Describe year-standardized centrality decline as such: it need not mean a state literally lost ties.

8. **Influence refits accept warned and nonconverged estimates, then use them to select dispute drops.** `R/09_influence.R:40–58`; `run_all.sh:134–139`.

   `suppressWarnings(coxph(...))` discards the very separation/convergence warnings that invalidate sweep fits. Only finite coefficients are required. Finite but unconverged estimates can therefore rank a dispute as influential and determine the top-5/top-10 exclusions. Null refits and missing-type refits disappear from the CSV, with only a total count left in the log. If writing `_loo.csv` succeeds and `_top.txt` fails, the runner skips the necessary rerun because it checks only `_loo.csv`.

   **Minimal fix:** reuse the sweep's validity policy, record every attempted unit and failure reason, and validate both output files before treating this step as finished. The contrast vector's linear/squared signs and any-source matching are correct for valid, correctly named endpoints; add explicit validation of `--q` names to prevent malformed contrasts from silently extending the named vector.

9. **The resampling gate is implemented, but model-specific validity and permutation consistency remain incomplete.** `R/08_resample.R:31–46, 56–58, 72–101`; `R/07_fit_sweep.R:148–149, 258–267`.

   Multiplicities are correctly drawn before parallel execution and applied uniformly to each event's alternatives. The B≥200/90% gate also suppresses `share_pos` as intended. However, one failed M1 draw discards that draw's valid M0 result; a failed full-sample M1 prevents pooled inference altogether. The gap eligibility check tests year t but not constant t−1 numerator years, whereas the sweep tests both. Drop reasons are written without their draw IDs. The sweep itself handles invalid warnings per model but does not catch thrown fit errors per model: a thrown M1 exception still causes the outer handler to discard usable M0 rows.

   For `perm_type` on an aggression/defense variant, the gap columns are rebuilt after relabeling, but existing `aggr_<role>`/`def_<role>` controls retain the original types. This is not a permutation of the specified typed model. It does not affect the runner's current base-only calls, but the script accepts these variant dumps.

   **Minimal fix:** preserve separate model/draw validity, align year eligibility with the sweep, retain draw IDs, catch model-specific errors, and rebuild typed controls from their common underlying variable after permuting labels—or refuse variant permutations explicitly. These corrections still do not supply exchangeability for the permutations; see B.

10. **“Event-weighted SD” still weights an event by its number of alternatives.** `R/07_fit_sweep.R:145–158`.

   `wsd(dRc,D$w)` runs over long-frame rows, so an event with 100 alternatives contributes 100w, while one with 10 contributes 10w. This is an alternative-row distribution weighted by event weights, not an equal-event/D8-weighted mixture over choice sets. **Minimal fix:** if the intended population is event-weighted choice sets, use row weight w/n_alternatives; if chosen-event changes are intended, normalize on chosen rows. Name and save the normalization population and constant. This changes “per SD” magnitudes and their comparison across samples, although a common positive rescaling alone does not change a coefficient's significance.

   The earlier nonoverlapping baseline and added nonlinear terms are present. The full model is an expanded response surface, not merely a relabeling of the original quadratic. The `decomp_extra` test correctly tests whether the added three terms per type are zero; it does not test the additional coefficient restrictions needed to reproduce the original current-gap-only surface. Do not interpret the linear change coefficient as the change effect everywhere once the full interactions are included.

11. **The aggressive-history coverage problem is flagged rather than solved; date conflicts are still clamped.** `R/06_make_variants.R:32–48, 57–69`.

   GML starts now take priority, and onset/entry defense anchors are separate. But absent GML dates still fall back to retained event minima; starts after entry are reset to the event year. Windows extending beyond 2010 receive a lower-bound aggression count. `aggr_censored` is saved but neither restricted out nor used to restore missing histories. Merely flagging it does not make the historical count comparable. **Minimal fix:** run the aggression sensitivity on complete, reconciled windows and compare the base model on that same sample; provide flagged-date cases separately. Distinguish first-action-originator history from independently coded aggressive conduct. Primary-source anchoring of mixed-dispute events is now disclosed but remains a substantive convention, not a uniquely correct pre-conflict date.

12. **The side-case sensitivity omits promoted joiners and is narrower than “drop these disputes.”** `R/05_dump_events.R:309–315`; `R/06_make_variants.R:114–120`; `README.md` main-settings table.

   `side_case` is assigned only after promotions and only where the final `grp==2`. An early initiating-side joiner in a reviewed dispute is promoted, loses the tag and survives both side-case drops—even though the initiating-side map determined whether that promotion was retained. The code deliberately drops remaining joiner strata, not all events from those disputes or every affected original joiner. **Minimal fix:** retain original-joiner status and side-map provenance before promotion, tag all affected events, and offer a drop of all such events. If saying entire disputes are dropped, match every source dispute as the ordinary drop variant does. Keep the narrower check as a separately labeled sensitivity.

13. **The appendix collector does not enforce a unique, complete analysis universe.** `R/11_summarize.R:14–29`; `run_all.sh:48–57, 155`.

   It reads every matching CSV recursively, counts estimate rows with `.N`, and does not assert uniqueness of `(group,run,spec_id,model,quantity)`. Overlapping files from test runs or changed jobs can inflate the apparent number of measures and weight an estimate repeatedly. The census combines invalid status across models; Wald summaries report `.N` including uncomputable p-values while the percentage excludes NA. The readable main table shows only the all-measures view; there is no failed-only or family-balanced view, no requested-versus-valid denominator per model, and no explicit window/selection multiplicity warning.

   **Minimal fix:** collect only outputs enumerated by a validated run manifest, reject duplicate keys and unexpected/missing spec IDs, and report requested/valid/skipped/invalid/error/undefined-test counts per model and quantity. Add failed-only, family-stratified and family-balanced summaries. Keep the current row-weighted grid percentage only as a clearly labeled descriptive summary.

### P3 — documentation and option hygiene

14. **Some advertised guarantees exceed the implemented checks.** `R/07_fit_sweep.R:34–56`; `README.md`; `docs/decisions.md`.

   The sweep refuses unknown option names, but still accepts irrelevant combinations such as `--decomp_terms=full` with `--decomp=0` and nonzero `--merror_k` with no measurement-error mode. Several scripts lack duplicate-option or positional-argument checks. The README says all system members are alternatives, whereas assembly also requires eligible positions, covariates and stage-2 availability. “Statistically indistinguishable” originator/joiner surfaces based on p=0.55–0.98 are not demonstrated equivalent; do not make the pooling decision sound established by a high p-value. **Minimal fix:** reject ignored options and state the actual risk set and pooling assumption. Retain the four-type comparison as a substantive check, not just an appendix formality.

## Fixes confirmed in source, within the stated limits

- Onset is explicitly passed by the runner, recorded in dumps and encoded in dump/sweep names. Candidate windows remain a separate validation problem above.
- The side map now distinguishes COW sides from initiating/target sides, uses participant-level originator flags and includes expected-side regression checks. Early target-side joiner promotions are undone. For final bcd, undoing an early initiating-side joiner promotion would not change its chooser type; for bcjs it would change originator versus joinA. The unresolved issues are composite-source inputs, case-tag coverage and historical meaning—not a repeat of the old unconditional Side-A rule.
- The supplied fatal logs show the defender cell stays at 219 across windows 0→1, while bilateral changes 503→478 and chooser 358→383. Four-type originators rise 36→141 and joinA falls 322→242. Thus the large four-type change is partly an explicit promotion by construction; bcd's net reclassification is only 25 events. These are supplied-log observations, not independently rebuilt counts.
- True GML dispute starts are preferred for both aggression and onset defense, and every source ID is excluded from aggression history. Ordinary dispute drops and influence exclusions match any source dispute.
- M0 sums complete sets of typed controls into pooled controls; M0t preserves them. Warning/nonfinite-fit validity is separate by model. The decomposition baseline excludes the current position year, nonlinear terms are available, and incomparable IGO baseline rows are skipped. Pooled-scale lag pairs use one position-panel scale, so their matched-sample information comparison avoids the old own-year-unit mismatch.
- The diplomacy builder no longer reads a future wave. Coding unobserved new states/pre-first-wave years as zero remains a measurement assumption, not proof of no diplomacy. Core/IGO reuse is consistent with the fact that their position-building code did not change; verification of the actual reused files is still missing.
- `R/03_validate_measures.R` is outcome-blind in its inputs. It reads positions, CINC and major-power status, not chosen targets or fitted results. Its rank/AUC direction, historical thresholds and China-rise definition match their stated formulas. Correlation with material power is a validation criterion, not independent validation of a separate relational construct. The historical 1e−15 comparison cannot be independently replicated without the RDS inputs. The Phase-A list has exactly 201 distinct, nonempty IDs; it is a locked cohort selected from the earlier construction, not automatically a fresh random sample of today's plausible measures after diplomacy was rebuilt.

## B. Design of the loop

- **Selection versus failed bargains:** an all-MID target-choice model plus a correctly timed fatality model can locate an association in confrontation choice versus subsequent escalation. It does not identify the causal effect of isolation or show that bargaining failure explains the fatal-sample target-choice pattern. With the current pair-entry membership outcome, even that prospective distinction is unavailable. A null interaction test does not establish absence of escalation selection.
- **Permutation labels need restraint.** dR shuffling breaks its correlation with material gaps, geography, alliances, repeated targets and the common state-year network; the same state can receive inconsistent positions across events. Type shuffling assumes exchangeability across entry dates, conflicts and originator/joiner processes, while preserving only unweighted event-type counts. Neither is a valid randomization distribution for the scientific null “no isolation mechanism” or the weaker conditional-logit null with correlated controls and clustered assignment. The plus-one tail calculation and gate do not cure this. Present them as artificial-assignment diagnostics, or replace them with model-based null simulations that preserve nuisance structure and dependence. Such simulations test the model, not causal isolation.
- **Measurement perturbations test fragility, not confounding correction.** The code adds a positive multiple of standardized defense/contiguity counts or one fixed random field to each state's position, then renormalizes the gap. This mixes measurement content, units and geography/defense signal. It does not remove unknown bias or calibrate a plausible measurement-error distribution. Use both signs, several independent noise draws, a justified magnitude and rank/correlation diagnostics; distinguish fixed-unit changes from renormalized-measure comparisons. The no-ATOP comparison is more directly interpretable for alliance overlap.
- **Influence-selected drops are deliberately adversarial.** Ranking cases by the main measure's coefficient decrease answers how concentrated that estimate is. The same data select the omitted cases and produce the refitted interval; those intervals are not post-selection-valid confirmation of a trimmed-population effect. Publish all leave-one-out results, overlap in mixed-source events, failed refits and cumulative changes. Also include historically defined exclusions chosen independently of the measured result.
- **Onset plus one month still uses information after target choice.** It may be a defensible date-error convention; it does not establish that recruitment preceded the choice. Enlarging the originator window can mechanically move bandwagoners into the category used to argue for coalition formation. The logged four-type originator count is no longer tiny at one month because of this recoding. Retain original participant status, entry lag and decisions separately. Do not treat the seven windows as seven independent replications or infer equality from a failed originator/joiner test.
- **Missing high-value check:** genuinely separate initial target choice from joining an existing conflict. The full-state joiner choice set remains unresolved, and the new side map cannot repair that estimand. A descriptive event study over future survivors is also insufficient to choose among pariah dynamics, anticipation and vulnerability. Audit the chronology and risk set of dominant cases before running thousands more variants. An interacting-dyad foundation remains an important sensitivity if the current event builder pairs noninteracting opposing participants.
- **Single most useful change:** replace Step B's membership regression with an explicitly timed, initially nonfatal risk set, and preserve originator versus joining decisions in that construction. This makes the proposed selection/escalation distinction assessable before spending a day on the full grid.

## C. Reporting the multiverse

- Lead with the prespecified main estimand, window, measure and direct contrasts, including uncertainty, sample size and weighted effective decisions. Report how the one-month/pooling choices were selected and show the four-type evidence where the mechanism is discussed. A 95% interval is not a 95% probability that the mechanism is true.
- Organize the appendix by substantive assumption: event foundation/risk set; side/window coding; measurement family; timing; controls; inference; case concentration. Each answers a different question. A total across measures × windows × variants has no meaningful “replication” denominator.
- For each window and run, show the main estimate, median/IQR or a distribution of estimates, paired changes on common measure/sample IDs, and all direct type contrasts. Give separate plausible, failing and all-measure results. Stratify by weighting, centrality, diplomacy and layer content; include the old IGO anchors regardless of plausibility. Family-balanced views are summaries under a disclosed weighting scheme, not a new probability of truth.
- Report valid/requested counts and every excluded status separately by model and quantity. Distinguish no estimate, an uncomputable Wald test and an interval including zero. State the bootstrap/permutation gate and successful-draw denominators. CI-exclusion shares are descriptive characteristics of highly correlated constructions; avoid “99% of specifications support the theory” in headings or conclusions.
- Keep the Phase-A cohort's original selection history and current plausibility flags separate. Show the full-grid results so loss of plausibility after rebuilding diplomacy does not silently change the cohort. Do not average bootstrap positivity, grid CI-exclusion percentages and permutation p-values into one evidence score.
- The appendix should retain negative results: full-decomposition terms matter; some side cases are substantively ambiguous; large-window originator labels partly reflect promotion; the case-trimmed estimates are selected diagnostics; Step B's surface-null does not establish equal fatality risks. Put those qualifications beside the relevant results.
- **Single most useful change:** replace the percentage-led appendix with a manifest-validated, family-stratified estimate display that shows all three validity sets, explicit denominators and paired assumption changes. Keep CI-exclusion percentages secondary and label them as grid summaries.

## Before a production run

Fix the window domain and isolate test outputs first. Then repair cache/completion validation and verify the primary-dispute side inputs. Gate the expensive run on those checks, define Step B's risk set explicitly, and enforce one fit-validity policy in sweep, influence and resampling. No wholesale rewrite is needed, but the supplied loop should not be treated as ready for an unattended production run.
